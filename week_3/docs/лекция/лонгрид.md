# Java 1. Неделя 3 — Классы и объекты

## Лонгрид

На первых двух неделях мы уже научились:

- хранить данные в переменных;
- использовать условия и циклы;
- разбивать алгоритм на методы;
- передавать данные через параметры;
- возвращать результат через `return`;
- хранить наборы значений в массивах;
- работать со строками.

До сих пор программа в основном выглядела так:

```text
данные
+
методы, которые эти данные обрабатывают
```

На этой неделе появляется новая модель:

```text
объект
├── состояние
└── поведение
```

Мы научимся объединять связанные данные и операции над ними в одном типе.

Именно с этого начинается нормальная работа с объектной моделью Java.

---

# 1. От разрозненных данных к классу

Представим, что программа хранит информацию о студенте.

После первых двух недель мы уже можем написать:

```java
String studentName = "Anna";
int studentAge = 18;
double studentAverageScore = 4.5;
```

Пока всё выглядит нормально.

Но теперь нам понадобился второй студент:

```java
String studentName1 = "Anna";
int studentAge1 = 18;
double studentAverageScore1 = 4.5;

String studentName2 = "Alex";
int studentAge2 = 19;
double studentAverageScore2 = 4.2;
```

А если студентов будет десять?

Или сто?

Очень быстро появляется набор переменных:

```text
studentName1
studentAge1
studentAverageScore1

studentName2
studentAge2
studentAverageScore2

studentName3
studentAge3
studentAverageScore3

...
```

Проблема здесь не только в количестве кода.

Главная проблема — связанные данные существуют отдельно.

Например:

```text
"Anna"
18
4.5
```

логически описывают **одного студента**, но язык пока не видит их как единое целое.

Из-за этого можно случайно перепутать:

```java
System.out.println(studentName1);
System.out.println(studentAge2);
```

Имя взяли у одного студента, возраст — у другого.

Нам нужен способ сказать Java:

> `Student` — это отдельный тип данных, у которого есть имя, возраст и средняя оценка.

Для этого используются **классы**.

```java
class Student {
    String name;
    int age;
    double averageScore;
}
```

Теперь мы описали новый тип:

```text
Student
```

### Основная идея

Класс позволяет объединить связанные данные и поведение в описание одной сущности.

```text
разрозненные данные
↓
понимаем, что они описывают одну сущность
↓
создаём класс
```

# 2. Класс и объект

Важно сразу разделить два понятия:

```text
класс
и
объект
```

Они связаны, но это не одно и то же.

## Класс

Класс описывает, **какими будут объекты определённого типа**.

Например:

```java
class Student {
    String name;
    int age;
}
```

Здесь мы сказали:

```text
любой Student
будет иметь

name
age
```

Но конкретного студента ещё не создали.

Можно представить класс как описание:

```text
Student

поля:
- name
- age
```

## Объект

Объект — конкретный экземпляр класса.

Например:

```java
Student student = new Student();
```

Теперь объект уже существует.

Разберём строку:

```java
Student student = new Student();
```

По частям:

```text
Student
→ тип переменной

student
→ имя переменной

new Student()
→ создание нового объекта
```

Создадим ещё один:

```java
Student anotherStudent = new Student();
```

Теперь существуют два разных объекта:

```text
student
→ Student №1

anotherStudent
→ Student №2
```

Даже если их поля пока одинаковые, это два разных объекта.

### Класс и объект

```text
класс
→ описание типа

объект
→ конкретный экземпляр этого типа
```

---

## Короткая аналогия с Python

В Python идея похожа:

```python
class Student:
    pass

student = Student()
```

В Java:

```java
class Student {
}

Student student = new Student();
```

Но дальше мы будем разбирать именно Java-модель: поля, конструкторы, ссылки, `this`, `static` и правила доступа.

# 3. Поля и состояние объекта

Вернёмся к классу:

```java
class Student {
    String name;
    int age;
    double averageScore;
}
```

Переменные, объявленные внутри класса и описывающие данные объекта, называются **полями**.

В нашем примере:

```text
name
age
averageScore
```

— поля.

Они описывают **состояние объекта**.

Создадим объект:

```java
Student student = new Student();
```

Запишем значения:

```java
student.name = "Anna";
student.age = 18;
student.averageScore = 4.5;
```

Теперь объект можно представить так:

```text
student
│
└── Student
    ├── name         → "Anna"
    ├── age          → 18
    └── averageScore → 4.5
```

Чтобы прочитать поле:

```java
System.out.println(student.name);
```

Получим:

```text
Anna
```

Чтобы изменить:

```java
student.age = 19;
```

После этого:

```text
student.age → 19
```

---

## У каждого объекта своё состояние

Создадим два объекта:

```java
Student first = new Student();
Student second = new Student();

first.name = "Anna";
first.age = 18;

second.name = "Alex";
second.age = 21;
```

Получаем:

```text
first
├── name → "Anna"
└── age  → 18

second
├── name → "Alex"
└── age  → 21
```

Если изменить:

```java
first.age = 19;
```

объект `second` не изменится.

```text
first.age  → 19
second.age → 21
```

Это два независимых объекта.

---

# 4. Значения полей по умолчанию

Рассмотрим:

```java
class Student {
    String name;
    int age;
    double averageScore;
    boolean active;
}
```

Создадим объект:

```java
Student student = new Student();
```

Мы пока ничего не присвоили полям.

Но поля уже существуют.

Java задаёт им начальные значения.

| Тип поля | Значение по умолчанию |
|---|---|
| `int` | `0` |
| `long` | `0` |
| `double` | `0.0` |
| `boolean` | `false` |
| `char` | символ с кодом `0` |
| ссылочный тип | `null` |

Поэтому сразу после:

```java
Student student = new Student();
```

можно представить объект так:

```text
name         → null
age          → 0
averageScore → 0.0
active       → false
```

Это важно отличать от локальных переменных внутри метода.

Например:

```java
public static void main(String[] args) {
    int age;

    System.out.println(age);
}
```

такой код не скомпилируется: локальной переменной `age` значение автоматически не назначается.

А поле объекта:

```java
class Student {
    int age;
}
```

получает `0`.

### Главное

```text
поля объекта
→ имеют значения по умолчанию

локальные переменные метода
→ должны быть инициализированы до использования
```

---

# 5. Методы объекта

До этой недели данные и операции часто существовали отдельно.

Например:

```java
Student student = new Student();

printStudent(student);
```

Метод:

```java
public static void printStudent(Student student) {
    System.out.println(student.name);
    System.out.println(student.age);
}
```

Но `printStudent()` логически относится именно к студенту.

Поэтому можно поместить поведение прямо в класс.

```java
class Student {

    String name;
    int age;

    void printInfo() {
        System.out.println(name);
        System.out.println(age);
    }
}
```

Теперь вызываем:

```java
student.printInfo();
```

Это читается естественнее:

```text
student
↓
printInfo()
```

Объект сам предоставляет операцию, связанную со своим состоянием.

---

## Состояние и поведение

Теперь в классе есть две группы членов:

```java
class Student {

    String name;
    int age;

    void printInfo() {
        ...
    }
}
```

Можно представить:

```text
Student
├── состояние
│   ├── name
│   └── age
│
└── поведение
    └── printInfo()
```

То есть:

```text
поля
→ состояние

методы
→ поведение
```

Это одна из центральных моделей недели.

---

## Метод объекта видит его поля

Обратите внимание:

```java
void printInfo() {
    System.out.println(name);
    System.out.println(age);
}
```

Метод не получает:

```text
name
age
```

через параметры.

Почему?

Потому что это метод конкретного объекта.

Он уже работает с его состоянием.

Например:

```java
Student first = new Student();
first.name = "Anna";
first.age = 18;

Student second = new Student();
second.name = "Alex";
second.age = 22;

first.printInfo();
second.printInfo();
```

Один и тот же код метода выполняется для разных объектов:

```text
first.printInfo()
→ name = "Anna"
→ age = 18

second.printInfo()
→ name = "Alex"
→ age = 22
```

# 6. Конструкторы

Пока объект создаётся так:

```java
Student student = new Student();
```

А потом мы отдельно задаём:

```java
student.name = "Anna";
student.age = 18;
```

Получается:

```text
создали объект
↓
объект существует с name = null, age = 0
↓
потом отдельно заполнили поля
```

Иногда это неудобно.

Мы хотим сразу сказать:

```text
создай Student
с именем Anna
и возрастом 18
```

Для этого используется **конструктор**.

```java
class Student {

    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Теперь:

```java
Student student = new Student("Anna", 18);
```

---

## Как выполняется создание объекта

Упрощённо:

```text
new Student("Anna", 18)
        ↓
создаётся объект
        ↓
вызывается конструктор
        ↓
name = "Anna"
age  = 18
        ↓
получаем готовый объект
```

Конструктор позволяет задать начальное состояние.

---

## Как узнать конструктор

Посмотрим:

```java
Student(String name, int age) {
    ...
}
```

У конструктора есть несколько характерных признаков.

### Имя совпадает с именем класса

```text
класс:
Student

конструктор:
Student(...)
```

### У конструктора нет возвращаемого типа

Метод:

```java
public int getAge() {
    return age;
}
```

Конструктор:

```java
Student(String name, int age) {
    ...
}
```

Перед `Student` нет:

```text
void
int
boolean
String
...
```

---

# 7. Конструктор без параметров

Рассмотрим класс:

```java
class Student {
    String name;
    int age;
}
```

Мы не написали ни одного конструктора.

Тогда можно:

```java
Student student = new Student();
```

Java предоставляет конструктор без параметров автоматически.

Но теперь добавим собственный:

```java
class Student {

    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

После этого:

```java
new Student("Anna", 18);
```

работает.

А:

```java
new Student();
```

уже не компилируется.

### Почему?

Когда мы объявили собственный конструктор, автоматический конструктор без параметров больше не предоставляется.

Если нужны оба варианта, их нужно объявить явно.

Например:

```java
class Student {

    String name;
    int age;

    Student() {
    }

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Теперь доступны оба:

```java
new Student();

new Student("Anna", 18);
```

### Главное

```text
нет собственного конструктора
→ Java даёт конструктор без параметров

объявили собственный
→ нужные варианты задаём сами
```

---

# 8. `this`

В конструкторе мы написали:

```java
Student(String name, int age) {
    this.name = name;
    this.age = age;
}
```

Здесь встречаются одинаковые имена:

```text
name
и
this.name
```

Но это разные вещи.

```text
name
→ параметр конструктора

this.name
→ поле текущего объекта
```

То же самое:

```text
age
→ параметр

this.age
→ поле объекта
```

---

## Что такое `this`

`this` — ссылка на **текущий объект**.

Например:

```java
void setAge(int age) {
    this.age = age;
}
```

Если вызываем:

```java
first.setAge(20);
```

то внутри метода:

```text
this
→ first
```

Если:

```java
second.setAge(30);
```

то:

```text
this
→ second
```

Один и тот же метод выполняется для разных объектов.

---

## Когда `this` особенно нужен

Если параметр называется так же, как поле:

```java
void setAge(int age) {
    this.age = age;
}
```

без `this`:

```java
void setAge(int age) {
    age = age;
}
```

код компилируется, но ничего полезного не делает.

Обе части:

```text
age = age
```

относятся к параметру метода.

Поле объекта не изменяется.

Правильно:

```java
this.age = age;
```

Здесь:

```text
this.age
→ поле

age
→ параметр
```

# 9. Почему прямой доступ к полям может быть проблемой

Создадим банковский счёт:

```java
class BankAccount {
    int balance;
}
```

Снаружи можно написать:

```java
BankAccount account = new BankAccount();

account.balance = 1000;
```

Но можно и:

```java
account.balance = -1_000_000;
```

Класс никак не контролирует изменение.

Если отрицательный баланс запрещён правилами программы, объект оказался в некорректном состоянии.

Нам нужен способ сказать:

```text
это внутреннее состояние объекта

изменять его можно
только через разрешённые операции
```

# 10. `private` и `public`

Для поля можно использовать:

```java
private
```

Например:

```java
class BankAccount {
    private int balance;
}
```

Теперь код снаружи класса не может напрямую написать:

```java
account.balance = -1_000_000;
```

Вместо этого класс предоставляет операции.

```java
class BankAccount {

    private int balance;

    public void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public int getBalance() {
        return balance;
    }
}
```

Теперь внешний код:

```java
account.deposit(1000);
```

А чтение:

```java
System.out.println(account.getBalance());
```

---

## Базовая модель доступа

На текущем уровне достаточно:

```text
private
→ внутренняя часть класса

public
→ доступно внешнему коду
```

Можно представить:

```text
внешний код
    ↓
public-методы
    ↓
проверки
    ↓
private-поля
```

### Главная идея

Объект может контролировать работу со своим состоянием.

---

## Что пока не разбираем

У Java есть и другие варианты доступа:

```text
package-private
protected
```

Но их смысл сильно связан с пакетами и наследованием.

Поэтому сейчас достаточно уверенно понимать:

```text
private
public
```

К остальным вариантам вернёмся позже.

# 11. Ссылочные типы

На прошлой неделе мы уже использовали:

```java
String text;
int[] numbers;
```

Это ссылочные типы.

Теперь мы создали собственный:

```java
Student student;
```

Сравним с примитивом.

## Примитив

```java
int age = 18;
```

Упрощённая модель:

```text
age
↓
18
```

## Объект

```java
Student student = new Student("Anna", 18);
```

Модель:

```text
student
   │
   │ ссылка
   ↓
┌──────────────┐
│ Student      │
│ name → Anna  │
│ age  → 18    │
└──────────────┘
```

Переменная `student` хранит **ссылку на объект**.

Не нужно воспринимать ссылку как конкретный физический адрес памяти.

Для нашего уровня достаточно:

> ссылка — значение, которое позволяет обратиться к объекту.

---

# 12. Несколько ссылок на один объект

Рассмотрим:

```java
Student first = new Student("Anna", 18);

Student second = first;
```

Очень важно:

```java
Student second = first;
```

**не создаёт новый объект**.

После этой строки:

```text
first  ─┐
        ├──→ один объект Student
second ─┘
```

Теперь изменим через `second`:

```java
second.age = 19;
```

А потом:

```java
System.out.println(first.age);
```

Результат:

```text
19
```

Почему?

Потому что:

```text
first
и
second

→ указывают на один объект
```

---

## Это уже знакомо по массивам

На прошлой неделе:

```java
int[] first = {1, 2, 3};
int[] second = first;

second[0] = 100;

System.out.println(first[0]);
```

Результат:

```text
100
```

Причина та же:

```text
first
second
  ↓
один массив
```

Теперь такая модель распространяется и на наши собственные классы.

---

# 13. Передача объекта в метод

Создадим:

```java
class Student {
    String name;
    int age;
}
```

Метод:

```java
public static void birthday(Student student) {
    student.age++;
}
```

Вызов:

```java
Student student = new Student();

student.age = 18;

birthday(student);

System.out.println(student.age);
```

Результат:

```text
19
```

---

## Что произошло?

Java всегда передаёт аргументы **по значению**.

Для объекта значением является ссылка.

Упрощённо:

```text
student в main
      ↓
 значение ссылки
      ↓ копируется
параметр student
      ↓
тот же объект
```

Поэтому метод получает свою локальную переменную `student`, но обе ссылки ведут к одному объекту.

Когда выполняется:

```java
student.age++;
```

изменяется сам объект.

После завершения метода изменение остаётся.

---

# 14. Изменить объект и переназначить ссылку — не одно и то же

Это принципиально важный момент.

Сначала изменение объекта:

```java
public static void birthday(Student student) {
    student.age++;
}
```

Здесь:

```text
ссылка
↓
объект
↓
меняем поле age
```

Изменение видно снаружи.

Теперь другой метод:

```java
public static void replace(Student student) {
    student = new Student("Bob", 30);
}
```

Вызов:

```java
Student student =
        new Student("Anna", 18);

replace(student);

System.out.println(student.name);
```

Результат:

```text
Anna
```

Почему не `Bob`?

Параметр метода — отдельная локальная переменная.

До присваивания:

```text
student в main ─────┐
                    ├──→ Anna
student в методе ───┘
```

После:

```java
student = new Student("Bob", 30);
```

получаем:

```text
student в main
→ Anna

student в методе
→ Bob
```

Локальную копию ссылки переназначили.

Переменная в вызывающем коде не изменилась.

### Главное

```text
student.age++
→ изменяем общий объект

student = new Student(...)
→ переназначаем локальную ссылку
```


```text
createStudent("Anna", 18)

           ↓
student
```

```java
    ...
}
```

```java
if (student != null) {
```

```text
→ объект существует
```

# 19. Методы экземпляра и `static`-методы

Метод экземпляра:

```java
public int getAge() {
    return age;
}
```

Вызов:

```java
student.getAge();
```

Для выполнения нужен конкретный объект.

Почему?

Потому что метод работает с:

```text
age
```

этого объекта.

---

Статический метод:

```java
public static int getStudentCount() {
    return count;
}
```

Вызов:

```java
Student.getStudentCount();
```

Конкретный объект не нужен.

## Базовое правило выбора

```text
метод работает
с состоянием конкретного объекта
↓
метод экземпляра
```

```text
операция относится
к классу в целом
↓
static
```

Пока этого правила достаточно.

# 20. Теперь понятнее `public static void main`

С первой недели мы писали:

```java
public static void main(String[] args) {
    ...
}
```

Тогда `static` воспринимали как часть стандартной формы.

Теперь можно осмыслить.

`main` — статический метод.

То есть для его вызова не требуется заранее создавать:

```java
new Main();
```

Упрощённо:

```text
JVM
↓
Main.main(...)
```

а не:

```text
new Main()
↓
main(...)
```

Это одна из причин, почему точка входа объявляется `static`.

# 21. `toString()`: как представить объект текстом

Создадим:

```java
Student student =
        new Student("Anna", 18);
```

Попробуем вывести:

```java
System.out.println(student);
```

Java умеет выводить объект, но стандартное текстовое представление обычно не содержит полезной для нас предметной информации.

Нам хотелось бы видеть:

```text
Student{name='Anna', age=18}
```

Для этого можно переопределить:

```java
@Override
public String toString() {
    return "Student{name='" + name
            + "', age=" + age + "}";
}
```

Теперь:

```java
System.out.println(student);
```

получает понятное строковое представление.

---

## Что делает `toString()`

Упрощённая модель:

```text
объект
↓
toString()
↓
String
```

Например:

```text
Student
↓
"Student{name='Anna', age=18}"
```

### Где полезно

- вывод в консоль;
- отладка;
- логирование;
- просмотр состояния объекта.

---

## Что такое `@Override`

В этом коде:

```java
@Override
public String toString() {
    ...
}
```

`@Override` показывает:

> Мы задаём свою версию метода, который уже существует у объектов Java.

Почему такой метод вообще есть у любого объекта, подробно станет понятнее позже, когда будем изучать наследование.

Сейчас достаточно знать:

```text
toString()
→ стандартная операция объекта

мы можем задать
своё текстовое представление
```

# 22. Сравнение объектов через `==`

На прошлой неделе мы уже встречали особенность сравнения `String`.

Теперь можем понять её через ссылочную модель.

Рассмотрим:

```java
Student first =
        new Student("Anna", 18);

Student second = first;
```

Проверим:

```java
System.out.println(first == second);
```

Результат:

```text
true
```

Потому что:

```text
first  ─┐
        ├──→ один объект
second ─┘
```

---

Теперь:

```java
Student first =
        new Student("Anna", 18);

Student second =
        new Student("Anna", 18);
```

Поля одинаковые.

Но:

```java
System.out.println(first == second);
```

даст:

```text
false
```

Почему?

Потому что это два разных объекта.

```text
first  → объект №1
second → объект №2
```

### Главное

Для объектов:

```text
==
→ проверяет, ссылаются ли переменные
  на один и тот же объект
```

# 23. Что такое смысловое равенство

Представим:

```java
Student first =
        new Student("Anna", 18);

Student second =
        new Student("Anna", 18);
```

Физически это два разных объекта.

Поэтому:

```java
first == second
```

даёт:

```text
false
```

Но с точки зрения нашей предметной области можно решить:

> Два студента с одинаковыми данными должны считаться равными.

Это уже другой вопрос.

Он называется **смысловым равенством**.

В Java для этого используется:

```java
equals()
```

---

# 24. `equals()`

Упрощённо:

```text
==
→ это один и тот же объект?

equals()
→ должны ли два объекта
  считаться равными по смыслу?
```

Для стандартных классов Java правило уже задано.

Например для `String`:

```java
String first = "Java";
String second = "Java";

System.out.println(first.equals(second));
```

Результат:

```text
true
```

Потому что строки содержат одинаковый текст.

---

## Для собственного класса правило задаёт разработчик

Для `Student` можно решить, что при сравнении важны:

```text
name
age
```

Например:

```text
Student("Anna", 18)
Student("Anna", 18)

→ равны
```

А:

```text
Student("Anna", 18)
Student("Anna", 19)

→ не равны
```

Точная реализация стандартного `equals()` требует нескольких механизмов Java, часть которых мы подробно изучим позже.

Поэтому на текущем уровне важно:

1. понимать отличие `==` от `equals()`;
2. понимать, что правило смыслового равенства задаёт класс;
3. уметь использовать сгенерированный IDE вариант для простого класса;
4. не пытаться запоминать сложный шаблон реализации наизусть.

---

## Связь со `String`

На второй неделе мы фиксировали правило:

```java
first.equals(second)
```

для сравнения содержимого строк.

Теперь причина стала понятнее.

`String` — объект.

```text
==
→ сравнение ссылок

equals()
→ сравнение строк по их смыслу,
  то есть по содержимому
```

# 26. Собираем класс целиком

Посмотрим на небольшой класс, в котором уже есть основные идеи недели.

```java
class Student {

    private String name;
    private int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void birthday() {
        age++;
    }

    public int getAge() {
        return age;
    }

    public String getName() {
        return name;
    }

    @Override
    public String toString() {
        return "Student{name='" + name
                + "', age=" + age + "}";
    }
}
```

Использование:

```java
Student student =
        new Student("Anna", 18);

student.birthday();

System.out.println(student.getAge());
System.out.println(student);
```

Результат:

```text
19
Student{name='Anna', age=19}
```

---

## Что здесь есть

```text
class Student
→ новый тип

private String name
private int age
→ состояние

Student(...)
→ конструктор

this
→ текущий объект

birthday()
getAge()
getName()
→ поведение

toString()
→ текстовое представление
```

Это уже полноценная базовая объектная модель.

# 27. Класс `BankAccount`: мотивационная задача

Попробуем применить модель к другой сущности.

Нам нужен банковский счёт.

Он должен хранить:

```text
owner
balance
```

Можно начать:

```java
class BankAccount {
    private String owner;
    private int balance;
```

Почему `balance` делаем `int`, а не `double`?

## Какое поведение нужно объекту?

Например:

```text
deposit(...)
withdraw(...)
getBalance()
toString()
```

Тогда объект можно мыслить так:

```text
BankAccount
├── состояние
│   ├── owner
│   └── balance
│
└── поведение
    ├── deposit(...)
    ├── withdraw(...)
    ├── getBalance()
    └── toString()
```

# 28. Почему поведение лучше хранить рядом с состоянием

Представим внешний код:

```java
account.balance -= amount;
```

Он напрямую меняет состояние.

Но классу лучше контролировать правила.

Например:

```text
нельзя внести отрицательную сумму

нельзя списать больше,
чем есть на счёте
```

Поэтому логичнее:

```java
account.deposit(500);
account.withdraw(200);
```

Сам объект решает, допустима ли операция.

Это и есть важный переход к объектному стилю:

```text
не просто храним данные
↓
объект отвечает
за корректную работу
со своим состоянием
```

# 30. Главное различие: объект и ссылка

Это одна из самых важных моделей недели.

Объект:

```text
Student
├── name
└── age
```

Ссылка:

```text
student
↓
позволяет обратиться к объекту
```

Поэтому возможны разные ситуации.

## Одна ссылка — один объект

```text
student
   ↓
Student
```

## Две ссылки — один объект

```text
first  ─┐
        ├──→ Student
second ─┘
```

## Ссылка без объекта

```text
student
↓
null
```

Если эта модель понятна, намного легче понимать:

- массивы;
- `String`;
- собственные классы;
- передачу объектов в методы;
- `==`;
- `null`.

# 31. Главное различие: объект и класс

Ещё одна важная модель.

```text
Student
→ класс
→ описание типа
```

```text
new Student(...)
→ создание объекта
```

```text
student
→ переменная со ссылкой
```

```text
student.name
→ состояние конкретного объекта
```

```text
student.printInfo()
→ поведение конкретного объекта
```

А:

```text
Student.count
Student.getStudentCount()
```

— члены класса, объявленные через `static`.
