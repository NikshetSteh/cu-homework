# Java 1. Неделя 3 — Домашнее задание

## BankAccount

Домашнее задание посвящено теме **классы и объекты**.

Нужно реализовать класс `BankAccount`, который представляет банковский счёт, хранит собственное состояние и сам контролирует допустимые изменения этого состояния.

В этом задании нет пошагового списка маленьких подзадач. Требования описывают поведение системы целиком, а часть проектирования нужно выполнить самостоятельно:

- определить поля класса;
- определить, какие данные должны быть скрыты;
- решить, какие публичные методы нужны для работы со счётом;
- определить, где должны находиться проверки;
- продумать взаимодействие нескольких объектов.

Все требования ниже **обязательны**.

Используйте только материал, изученный к концу третьей недели.

---

# 1. Банковский счёт

Реализуйте класс:

```java
BankAccount
```

Каждый объект должен описывать отдельный банковский счёт.

Для счёта необходимо хранить как минимум:

- номер счёта;
- имя владельца;
- текущий баланс;
- заблокирован ли счёт.

Внутреннее состояние объекта не должно быть доступно для произвольного изменения снаружи.

Используйте `private` там, где внешний код не должен напрямую менять данные объекта.

Для создания счёта используйте конструктор.

При создании объекта должны выполняться правила:

- начальный баланс не может быть отрицательным;
- новый счёт создаётся незаблокированным;
- после завершения конструктора объект находится в корректном состоянии.

Самостоятельно определите:

- точный набор полей;
- параметры конструктора;
- какие значения нужно позволить читать снаружи;
- какие публичные методы нужны для дальнейших сценариев.

---

# 2. Операции со счётом

Счёт должен поддерживать:

- пополнение;
- снятие денег;
- блокировку;
- разблокировку;
- получение информации о текущем состоянии.

## Пополнение

Пополнение разрешено только если:

- сумма положительная;
- счёт не заблокирован.

Если операция недопустима, баланс не меняется.

## Снятие

Снятие разрешено только если одновременно выполняются все условия:

- сумма положительная;
- счёт не заблокирован;
- денег на счёте достаточно;
- за одну операцию снимается не больше `1000`.

Если хотя бы одно условие нарушено, состояние счёта не меняется.

## Важное требование

Проверки должны находиться внутри `BankAccount`.

Внешний код не должен делать так:

```text
сначала проверить баланс
сначала проверить блокировку
сначала проверить лимит
↓
и только потом вручную менять balance
```

Внешний код должен попросить объект выполнить операцию, а сам объект должен решить, разрешена она или нет.

# 3. Состояние конкретного объекта и состояние класса

Программа должна уметь определить, сколько объектов `BankAccount` было создано.

Это значение относится ко всему классу, а не к одному конкретному счёту.

Самостоятельно определите:

- какое поле здесь должно быть `static`;
- когда его значение должно изменяться;
- нужен ли статический метод для получения результата.

После создания трёх разных счетов программа должна показывать:

```text
Создано счетов: 3
```

При этом каждый счёт должен по-прежнему иметь собственный независимый баланс и собственное состояние блокировки.

# 4. Текстовое представление объекта

Переопределите `toString()`.

Объект должен удобно выводиться в консоль.

В строке должны быть видны как минимум:

- номер счёта;
- владелец;
- баланс;
- состояние блокировки.

Точный формат выберите самостоятельно.

Например, допустим результат вида:

```text
BankAccount{accountNumber='EE001', owner='Anna', balance=1000, blocked=false}
```

но повторять именно этот формат не обязательно.

# 5. Сравнение счетов

В рамках этого задания банковский счёт определяется **номером счёта**.

Два разных объекта считаются равными по смыслу, если у них одинаковый номер счёта.

Например:

```java
BankAccount first =
        new BankAccount("EE001", "Anna", 1000);

BankAccount second =
        new BankAccount("EE001", "Anna", 5000);
```

Это два разных объекта, поэтому:

```text
first == second
→ false
```

Но по правилам задания они представляют один и тот же банковский счёт:

```text
first.equals(second)
→ true
```

Переопределите `equals()` средствами IntelliJ IDEA.

При сравнении используйте номер счёта.

Не нужно писать стандартный шаблон `equals()` по памяти.

После реализации вы должны уметь объяснить разницу:

```text
==
→ один ли это объект

equals()
→ считаем ли мы два объекта равными по смыслу
```

# 6. Несколько ссылок на один объект

Добавьте в демонстрационный код следующий сценарий.

Создайте один счёт:

```java
BankAccount first =
        new BankAccount("EE100", "Anna", 1000);
```

Затем создайте вторую переменную, которая указывает на тот же объект:

```java
BankAccount second = first;
```

Измените состояние счёта через `second`.

После этого проверьте состояние через `first`.

Вы должны уметь объяснить:

- сколько объектов было создано;
- сколько существует переменных ссылочного типа;
- что происходит при `second = first`;
- почему изменение через одну переменную видно через другую.

После этого измените сценарий:

```java
second = new BankAccount(...);
```

и проверьте, на какие объекты теперь указывают `first` и `second`.

В программе должен быть хотя бы один отдельный `static`-метод, который получает `BankAccount` как аргумент и выполняет осмысленное действие с этим объектом.

Не копируйте заранее заданную сигнатуру.

Например, метод может:

- проверить состояние счёта.

При работе с объектом используйте его публичные методы.

# 9. `null`

Добавьте сценарий, в котором переменная типа `BankAccount` не указывает ни на один объект:

```java
BankAccount account = null;
```

Код должен безопасно обработать такую ситуацию.

Нельзя вызывать методы объекта, если ссылка может содержать `null`, не выполнив необходимую проверку.

Программа не должна завершаться с ошибкой из-за такого сценария.

После выполнения вы должны уметь объяснить:

```text
BankAccount account = null;
```

не создаёт объект.

# 10. Перевод между счетами

Добавьте в `BankAccount` возможность перевести деньги на другой счёт.

Продумайте сигнатуру метода самостоятельно.

Перевод должен изменять состояние двух объектов:

```text
счёт отправителя
+
счёт получателя
```

## Правила перевода

Перевод разрешён только если одновременно выполняются все условия:

- сумма положительная;
- у отправителя достаточно денег;
- отправитель не заблокирован;
- получатель существует;
- получатель не заблокирован;
- отправитель и получатель — разные объекты.

Если хотя бы одно условие нарушено:

> **состояние обоих счетов должно остаться прежним.**

## Пример

До операции:

```text
Anna: 1000
Alex: 500
```

После перевода `300`:

```text
Anna: 700
Alex: 800
```

## Обязательные сценарии проверки

Проверьте:

1. успешный перевод;
2. недостаточно денег;
3. нулевую сумму;
4. отрицательную сумму;
5. заблокированного отправителя;
6. заблокированного получателя;
7. перевод самому себе;
8. `null` вместо получателя.

Особенно внимательно проверьте, что неуспешная операция не приводит к ситуации:

```text
у отправителя деньги уже снялись,
а получатель их не получил
```

# 13. Требования к качеству решения

Перед сдачей проверьте:

- внутреннее состояние счёта нельзя произвольно менять снаружи;
- нельзя получить отрицательный баланс через разрешённые операции;
- заблокированный счёт ведёт себя согласно требованиям;
- неуспешные операции не изменяют состояние;
- `static` используется только для данных, относящихся к классу в целом;
- `toString()` выводит полезную информацию;
- `equals()` соответствует правилу равенства по номеру счёта;
- обработка `null` безопасна;
- перевод не может частично изменить два объекта;
- `main()` не содержит внутреннюю логику `BankAccount`;
- код отформатирован;
- имена полей, переменных и методов отражают их назначение;
- отсутствует ненужный закомментированный код.


`BankAccount` должен сам отвечать за корректность своего состояния.

После выполнения задания вы должны понимать:

