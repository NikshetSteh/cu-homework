# Java 1. Неделя 7 — дополнительная задача для семинара

# Работа в Яндекс Контесте — мониторинг серверов


Нужно будет:

- прочитать условие;
- реализовать решение в одном файле `Main.java`;
- при необходимости объявить в этом же файле дополнительные классы;
- отправить решение в Яндекс Контест;
- проверить открытые примеры;
- затем пройти скрытые тесты.

Главная цель — привыкнуть к формату:

```text
stdin
→ программа
→ stdout
→ автоматическая проверка
```

Контест сравнивает вывод программы с ожидаемым результатом, поэтому формат вывода является частью контракта задачи.

---

# Бизнес-сценарий

Есть система мониторинга серверов.

В течение некоторого периода от серверов приходят события. Каждое событие содержит:

```text
serverId;type;duration
```

Например:

```text
101;OK;120
102;ERROR;500
101;WARN;230
103;ERROR;800
```

Где:

- `serverId` — целочисленный идентификатор сервера;
- `type` — тип события;
- `duration` — длительность обработки запроса в миллисекундах.

Допустимые типы событий:

```text
OK
WARN
ERROR
```

По потоку событий нужно построить итоговую статистику.

---

# Что нужно сделать

Первая строка входа содержит число:

```text
N
```

Далее идут `N` строк событий:

```text
serverId;type;duration
```

Гарантируется:

```text
1 <= N <= 100
serverId > 0
duration >= 0
```

Для всех входных строк гарантируется корректный формат.

Нужно вычислить:

1. общее количество событий;
2. количество событий `ERROR`;
3. суммарную длительность всех событий;
4. максимальную длительность;
5. `serverId` события с максимальной длительностью;
6. длину самой длинной последовательности подряд идущих `ERROR`.

Если максимальная длительность встречается несколько раз, нужно выбрать событие с меньшим `serverId`.

---

# Формат вывода

Вывод должен состоять ровно из шести строк:

```text
EVENTS=<count>
ERRORS=<errorCount>
TOTAL_DURATION=<total>
MAX_DURATION=<max>
SLOWEST_SERVER=<serverId>
LONGEST_ERROR_STREAK=<count>
```

Лишний текст выводить не нужно.

---

# Пример

## Ввод

```text
7
101;OK;120
102;ERROR;500
103;ERROR;250
101;WARN;300
104;ERROR;800
105;ERROR;100
106;OK;50
```

## Вывод

```text
EVENTS=7
ERRORS=4
TOTAL_DURATION=2120
MAX_DURATION=800
SLOWEST_SERVER=104
LONGEST_ERROR_STREAK=2
```

# Требования к решению

Решение сдаётся одним файлом:

```text
Main.java
```

Внутри файла можно объявлять несколько классов.

Например, технически допустима такая структура:

```java
public class Main {
    public static void main(String[] args) {
        // точка входа
    }
}

class SomeClass {
}

class AnotherClass {
}
```

Только `Main` должен быть `public`.

Конкретную архитектуру решения нужно выбрать самостоятельно.

Используй конструкции, изученные к неделе 7:

- условия и циклы;
- методы;
- массивы;
- `String`;
- классы и объекты;
- исключения;
- `BufferedReader`.

Не используй:

- коллекции;
- Stream API;
- lambda;
- сторонние библиотеки.

# Перед отправкой в Контест

Проверь решение хотя бы на следующих случаях.

## Один элемент

```text
1
7;OK;15
```

Ожидаемый результат:

```text
EVENTS=1
ERRORS=0
TOTAL_DURATION=15
MAX_DURATION=15
SLOWEST_SERVER=7
LONGEST_ERROR_STREAK=0
```

---

## Все события — ошибки

```text
4
10;ERROR;10
11;ERROR;20
12;ERROR;30
13;ERROR;40
```

Ожидаемый результат:

```text
EVENTS=4
ERRORS=4
TOTAL_DURATION=100
MAX_DURATION=40
SLOWEST_SERVER=13
LONGEST_ERROR_STREAK=4
```

---

## Одинаковая максимальная длительность

```text
3
20;ERROR;500
10;OK;500
30;WARN;100
```

Максимальная длительность равна `500` у двух событий.

Нужно выбрать меньший `serverId`.

Ожидаемый результат:

```text
EVENTS=3
ERRORS=1
TOTAL_DURATION=1100
MAX_DURATION=500
SLOWEST_SERVER=10
LONGEST_ERROR_STREAK=1
```

---

# Что важно заметить в Яндекс Контесте

Открытый пример нужен, чтобы проверить:

- правильно ли читается вход;
- совпадает ли формат вывода;
- не выводится ли лишний текст;
- корректно ли запускается `Main.java`.

Но прохождение открытого примера не означает, что программа полностью правильная.

После отправки решение проверяется и на скрытых тестах.

Например, программа может пройти пример из условия, но ошибиться на:

- одном событии;
- отсутствии `ERROR`;
- серии `ERROR` в конце;
- одинаковой максимальной длительности;
- `duration = 0`;
- максимальном `N`.

# Практика с WA

Для знакомства с платформой полезно один раз намеренно отправить решение с неправильным форматом.

Например:

```java
System.out.println("Errors: " + errorCount);
```

вместо:

```java
System.out.println("ERRORS=" + errorCount);
```

Логически число может быть правильным, но Контест выдаст:

```text
WA
```

потому что ожидаемый вывод и фактический вывод различаются.

Главная модель:

```text
правильный алгоритм
+
точный формат вывода
=
успешная посылка
```
