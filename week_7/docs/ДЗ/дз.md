# Java 1. Неделя 7 — Домашнее задание

# Генератор наборов входных данных

## Задача

Напиши консольную утилиту, которая генерирует текстовые файлы с целыми числами.

Программа должна поддерживать два режима работы:

```text
CONSOLE
IMPORT
```

В режиме `CONSOLE` команды вводятся пользователем.

В режиме `IMPORT` команды читаются из текстового файла построчно.

Обе схемы должны использовать одну и ту же логику разбора и выполнения команд.

---

# Формат команд

Поддерживаются три команды:

## `RANGE`

```text
RANGE|<fileName>|<start>|<end>|<step>
```

Пример:

```text
RANGE|evens.txt|2|10|2
```

создаёт файл:

```text
2
4
6
8
10
```

Разрешено движение в обе стороны:

```text
RANGE|decrease.txt|5|-1|-2
```

результат:

```text
5
3
1
-1
```

Некорректны случаи:

```text
step = 0
```

или когда знак `step` не позволяет двигаться от `start` к `end`.

---

## `REPEAT`

```text
REPEAT|<fileName>|<value>|<count>
```

Пример:

```text
REPEAT|zeros.txt|0|4
```

создаёт:

```text
0
0
0
0
```

`count` должен быть больше `0`.

---

## `ALTERNATE`

```text
ALTERNATE|<fileName>|<first>|<second>|<count>
```

Пример:

```text
ALTERNATE|flags.txt|1|0|6
```

создаёт:

```text
1
0
1
0
1
0
```

`count` должен быть больше `0`.

---

# Режим `CONSOLE`

После запуска пользователь выбирает режим и указывает выходной каталог.

Пример:

```text
Mode:
CONSOLE

Output directory:
generated
```

После этого вводятся команды:

```text
RANGE|evens.txt|2|10|2
REPEAT|zeros.txt|0|4
ALTERNATE|flags.txt|1|0|6
END
```

`END` завершает ввод.

Некорректная команда не должна завершать программу.

Например:

```text
RANGE|bad.txt|1|10|0
```

должна быть отклонена, после чего программа продолжает принимать следующие команды.

---

# Режим `IMPORT`

В этом режиме пользователь дополнительно указывает путь к plan-файлу.

Пример:

```text
Mode:
IMPORT

Plan file:
plans/demo.plan

Output directory:
generated
```

`plans/demo.plan`:

```text
RANGE|evens.txt|2|20|2
REPEAT|zeros.txt|0|5
BROKEN
ALTERNATE|flags.txt|1|0|8
RANGE|wrong.txt|10|1|2
REPEAT|hundreds.txt|100|3
RANGE|decrease.txt|5|-1|-2
```

Файл нужно читать построчно.

Некорректная команда не должна останавливать импорт остальных строк.

---

# Выходные файлы

Для каждой корректной команды создаётся отдельный файл в указанном выходном каталоге.

Кроме них программа должна создать:

```text
manifest.txt
rejected-commands.txt
```

## `manifest.txt`

Для каждой успешно выполненной команды:

```text
<fileName>|<type>|<generatedCount>
```

Например:

```text
evens.txt|RANGE|10
zeros.txt|REPEAT|5
flags.txt|ALTERNATE|8
hundreds.txt|REPEAT|3
decrease.txt|RANGE|4
```

## `rejected-commands.txt`

Для каждой отклонённой команды:

```text
<source>|<lineNumber>|<reason>|<originalCommand>
```

Например:

```text
IMPORT|3|unknown command|BROKEN
IMPORT|5|invalid RANGE direction|RANGE|wrong.txt|10|1|2
```

Для `CONSOLE` также веди номер введённой команды.

Формулировки `reason` можешь выбрать самостоятельно, но они должны быть понятными и последовательными.

---

# Итоговая статистика

После завершения программа должна вывести:

```text
Commands processed: <число>
Generated files: <число>
Rejected commands: <число>
Generated values: <число>
Largest file: <имя или n/a>
Largest file values: <число или n/a>
```

Для plan-файла:

```text
RANGE|evens.txt|2|20|2
REPEAT|zeros.txt|0|5
BROKEN
ALTERNATE|flags.txt|1|0|8
RANGE|wrong.txt|10|1|2
REPEAT|hundreds.txt|100|3
RANGE|decrease.txt|5|-1|-2
```

ожидается:

```text
Commands processed: 7
Generated files: 5
Rejected commands: 2
Generated values: 30
Largest file: evens.txt
Largest file values: 10
```

---

# Ошибки

Создай собственное исключение для некорректной команды, например:

```text
InvalidGenerationCommandException
```

Оно должно использоваться для ошибок формата или значений команды.

Например:

```text
UNKNOWN
REPEAT|x.txt|5|0
RANGE|x.txt|a|10|1
RANGE|x.txt|1|10|0
```

Ошибки работы с файлами должны обрабатываться отдельно как `IOException`.

Не смешивай:

```text
команда некорректна
```

и:

```text
файл невозможно открыть или записать
```

---

# Требования

В решении обязательно используй:

```text
Scanner
Path
Files
BufferedReader
BufferedWriter
UTF-8
try-with-resources
исключения
классы и методы
```

Выходной каталог программа должна создавать самостоятельно.

Пути собирай через `Path`, а не конкатенацией строк.

Большие выходные файлы должны генерироваться постепенно.

Например, команда:

```text
REPEAT|large.txt|1|1000000
```

не должна приводить к созданию массива на миллион элементов.

Plan-файл в режиме `IMPORT` также должен читаться постепенно.

---

# Ограничения

Не используй:

- коллекции;
- Stream API;
- lambda;
- `Files.readAllLines(...)`;
- `Files.lines(...)`;
- сторонние библиотеки.

Не требуется хранить все команды или все сгенерированные значения в памяти.


```text

0

1
0
```

# Дополнительно

Добавь новый тип генерации:

```text
BLOCK
```

Формат:

```text
BLOCK|<fileName>|<first>|<firstCount>|<second>|<secondCount>|<blocks>
```

Например:

```text
BLOCK|signal.txt|1|2|0|3|2
```

создаёт:

```text
1
1
0
0
0
1
1
0
0
0
```

Некорректны:

```text
firstCount <= 0
secondCount <= 0
blocks <= 0
```

Новый тип должен встроиться в уже существующую программу, а не реализовываться отдельным параллельным сценарием.

---

# Критерии готовности

Домашняя работа готова, если:

- работают оба режима: `CONSOLE` и `IMPORT`;
- поддерживаются `RANGE`, `REPEAT`, `ALTERNATE`;
- корректные команды создают ожидаемые файлы;
- некорректные команды не останавливают дальнейшую обработку;
- plan-файл читается построчно;
- большие файлы генерируются без хранения всех значений в памяти;
- создаются `manifest.txt` и `rejected-commands.txt`;
- итоговая статистика считается во время работы программы;
- пути представлены через `Path`;
- используется UTF-8;
- ресурсы закрываются через try-with-resources;
- ошибки команд отделены от `IOException`;
- не используются коллекции и Stream API.
