# Задача

Нужно реализовать упрощённую интерактивную версию логики игры **2048**.

Игровое поле имеет размер:

```text
4 × 4
```

Каждая клетка содержит либо:

```text
0
```

что означает пустую клетку,

либо положительное число:

```text
2
4
8
16
32
...
```

Игрок последовательно вводит команды:

```text
l
r
u
d
```

где:

```text
l — сдвиг влево
r — сдвиг вправо
u — сдвиг вверх
d — сдвиг вниз
```

После каждой команды программа должна изменить игровое поле по правилам 2048 и вывести новое состояние.

---

# Начальное поле

Для основной проверки используй:

```java
int[][] board = {
        {2, 0, 2, 4},
        {2, 2, 4, 4},
        {0, 4, 4, 8},
        {2, 0, 2, 2}
};
```

Поле можно задавать непосредственно в `main`.

---

# Ввод команд

Для этой задачи разрешено использовать `Scanner`, несмотря на то что подробно он будет разобран позже.

Достаточно минимальной модели:

```java
import java.util.Scanner;
```

```java
Scanner scanner = new Scanner(System.in);
String command = scanner.nextLine();
```

Не нужно изучать дополнительные возможности `Scanner`.

Программа должна запрашивать команды повторно, пока игра не завершится.

Допустимые команды:

```text
l
r
u
d
```

Если введена другая строка, например:

```text
x
left
1
```

поле не должно изменяться.

Программа должна вывести:

```text
Unknown command
```

и снова запросить ход.

---

# Правила движения

При вводе команды все плитки двигаются максимально далеко в соответствующем направлении.

Пустые клетки не препятствуют движению.

Например, при движении влево:

```text
[2, 0, 0, 4]
```

превращается в:

```text
[2, 4, 0, 0]
```

При движении вправо:

```text
[2, 0, 0, 4]
```

превращается в:

```text
[0, 0, 2, 4]
```

---

# Объединение плиток

Если две одинаковые плитки сталкиваются при движении, они объединяются в одну плитку с удвоенным значением.

Например:

```text
[2, 2, 0, 0]
```

после движения влево:

```text
[4, 0, 0, 0]
```

Ещё пример:

```text
[4, 4, 8, 0]
```

после движения влево:

```text
[8, 8, 0, 0]
```

---

# Главное правило объединения

Одна плитка может участвовать в объединении **не более одного раза за один ход**.

Например:

```text
[2, 2, 2, 2]
```

после движения влево должна стать:

```text
[4, 4, 0, 0]
```

а не:

```text
[8, 0, 0, 0]
```

Также:

```text
[2, 2, 4, 0]
```

после движения влево:

```text
[4, 4, 0, 0]
```

а не:

```text
[8, 0, 0, 0]
```

---

# Порядок объединения

Порядок определяется направлением движения.

Например:

```text
[2, 2, 2, 0]
```

при движении влево:

```text
[4, 2, 0, 0]
```

При движении вправо:

```text
[0, 0, 2, 4]
```

То есть результат зависит от стороны, к которой двигаются плитки.

---

# Счёт

Программа должна хранить игровой счёт:

```java
int score
```

Изначально:

```text
score = 0
```

При каждом объединении к счёту добавляется значение новой плитки.

Например:

```text
2 + 2 → 4
```

добавляет:

```text
+4
```

А:

```text
8 + 8 → 16
```

добавляет:

```text
+16
```

Если за один ход произошло несколько объединений, учитываются все.

Например:

```text
[2, 2, 4, 4]
```

после движения влево:

```text
[4, 8, 0, 0]
```

Счёт увеличивается на:

```text
4 + 8 = 12
```

---

# Новые плитки

В этой учебной версии **новые плитки после хода не появляются**.

Это сделано специально: задача посвящена работе с массивами, методами и алгоритмом движения.

Не нужно:

- использовать случайные числа;
- генерировать новые `2`;
- искать случайную свободную клетку.

---

# Ход, который ничего не изменил

Иногда команда допустима, но поле после неё остаётся таким же.

Например:

```text
[2, 4, 8, 16]
```

уже полностью сдвинута влево.

Команда:

```text
l
```

для такой строки ничего не изменяет.

Для всей доски ход считается **изменившим поле**, если изменилась хотя бы одна клетка.

Программа должна считать:

```text
количество успешных ходов
```

То есть количество команд `l`, `r`, `u`, `d`, которые действительно изменили поле.

Некорректные команды в этот счётчик не входят.

Команды, которые не изменили поле, тоже не входят.

---

# Завершение игры

Игра заканчивается автоматически, когда больше невозможно сделать ни одного хода.

Ход невозможен, если одновременно:

- на поле нет пустых клеток;
- нет двух одинаковых соседних плиток по горизонтали;
- нет двух одинаковых соседних плиток по вертикали.

Например:

```text
2   4   8   16
4   8   16  32
8   16  32  64
16  32  64  128
```

для такого поля игра завершена.

После завершения вывести:

```text
GAME OVER
```

---

# Вывод поля

После запуска программа должна показать начальное поле.

После каждого корректного хода нужно снова вывести поле.

Например:

```text
2    0    2    4
2    2    4    4
0    4    4    8
2    0    2    2

Score: 0
Move: 
```

После команды:

```text
l
```

поле должно стать:

```text
4    4    0    0
4    8    0    0
8    8    0    0
4    2    0    0
```

Счёт увеличится на:

```text
28
```

потому что произошли объединения:

```text
2 + 2 → 4
2 + 2 → 4
4 + 4 → 8
4 + 4 → 8
2 + 2 → 4
```

Итого:

```text
4 + 4 + 8 + 8 + 4 = 28
```

---

# Что вывести после завершения игры

После `GAME OVER` вывести:

```text
Final score: ...
Successful moves: ...
Maximum tile: ...
```

Где:

- `Final score` — итоговый счёт;
- `Successful moves` — число ходов, реально изменивших поле;
- `Maximum tile` — максимальная плитка на поле.

# Обязательная декомпозиция

Всю логику нельзя писать внутри `main`.

`main` должен в основном:

- создавать начальное поле;
- создавать `Scanner`;
- запускать игровой цикл;
- читать команду;
- вызывать методы;
- выводить результаты.

Конкретную декомпозицию программы на методы **нужно определить самостоятельно**.

Это часть advanced-задачи.

Не даётся обязательный список методов вида:

```text
moveLeft(...)
moveRight(...)
...
```

Самостоятельно реши:

- какие операции являются отдельными подзадачами;
- какие данные нужно передавать в методы;
- что методы должны возвращать;
- где должна изменяться игровая доска;
- как сообщить игровому циклу, изменился ли ход;
- как учитывать полученные очки.

Допускается создавать вспомогательные методы и временные одномерные массивы.

### Как получить случайное число

Для этого дополнения разрешено использовать:

```java
Math.random()
```

Минимальная модель:

```java
double random = Math.random();
```

`Math.random()` возвращает случайное значение:

```text
0.0 <= random < 1.0
```

Например, если нужно получить случайное целое число от `0` до `count - 1`:

```java
int index = (int) (Math.random() * count);
```

Подробно работу генераторов случайных чисел разбирать не нужно.

### Требования

Нужно самостоятельно продумать алгоритм, который:

- определяет количество свободных клеток;
- случайным образом выбирает одну из них;
- помещает туда значение `2`;
- не изменяет уже занятые клетки;
- ничего не делает, если свободных клеток нет.

Нельзя заранее выбирать случайные координаты до тех пор, пока не попадётся пустая клетка:

```text
случайная строка
+
случайный столбец
+
повторять до успеха
```

Такой подход может работать долго при почти заполненном поле.

Постарайся выбрать свободную клетку за конечное число проходов по полю.

### Изменение игрового цикла

С дополнительным режимом один успешный ход выглядит так:

```text
команда пользователя
↓
сдвиг и объединение плиток
↓
проверка: изменилось ли поле
↓
если изменилось — добавить случайную плитку 2
↓
вывести новое поле
↓
проверить GAME OVER
```
