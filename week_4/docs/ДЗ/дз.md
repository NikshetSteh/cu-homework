# Умная теплица

В теплице есть несколько грядок.

Для каждой грядки нужно контролировать влажность почвы. Вода хранится в общем баке. Система должна сама определять, сколько воды нужно конкретной грядке, и безопасно выполнять полив.

По мере выполнения задания программа должна пройти путь:

```text
отдельные классы
↓
разделение ответственности
↓
композиция
↓
делегирование
↓
контракт через interface
↓
система взаимодействующих объектов
```

Все этапы обязательны.

# Общие ограничения

Используйте только материал, изученный к концу недели 4.

Можно использовать:

- классы и объекты;
- конструкторы;
- `private` / `public`;
- методы;
- массивы;

- `implements`;
- интерфейс как тип переменной, поля и параметра;

Исходные данные можно создавать непосредственно в `main()`.

`Scanner` не требуется.

# 1. Грядка контролирует своё состояние

Создайте класс:

```java
PlantBed
```

Он представляет одну грядку в теплице.

Для грядки нужно хранить:

```text
id
plantName
moisture
```

где:

```text
moisture
→ влажность почвы в процентах
```

Допустимый диапазон:

```text
0 <= moisture <= 100
```

Все поля должны быть защищены от произвольного изменения снаружи.

## Создание грядки

Грядка создаётся через конструктор.

Например:

```java
PlantBed tomatoes =
        new PlantBed(
                "B-101",
                "Tomatoes",
                35
        );
```

После конструктора объект должен находиться в корректном состоянии.

Недопустимая начальная влажность не должна приводить к созданию объекта с:

```text
moisture < 0
```

или:

```text
moisture > 100
```

Конкретный способ обработки некорректного значения выберите самостоятельно в рамках уже изученных конструкций.

---

## Полив грядки

Добавьте операцию:

```java
boolean water(int liters)
```

Правила:

- количество литров должно быть положительным;
- `1` литр увеличивает влажность на `10`;
- влажность не может стать больше `100`;
- если операция недопустима, состояние не меняется;
- метод возвращает `true`, если полив выполнен.

Пример:

```text
до:
moisture = 30

действие:
water(2)

после:
moisture = 50
```

---

## Чтение состояния

Внешний код должен иметь возможность узнать:

- `id`;
- название растения;
- текущую влажность.

Но не должен иметь возможность написать:

```java
bed.moisture = -500;
```

или обойти правила другим прямым изменением поля.

---

# 2. Бак с водой — отдельная ответственность

Вода для полива хранится не внутри грядки.

Создайте отдельный класс:

```java
WaterTank
```

Он должен хранить:

```text
capacity
currentWater
```

где:

```text
capacity > 0
```

и всегда:

```text
0 <= currentWater <= capacity
```

## Публичные операции

Продумайте методы, позволяющие:

- узнать доступное количество воды;
- проверить, хватает ли воды;
- забрать указанное количество воды;
- пополнить бак.

Пример:

```text
capacity = 100
currentWater = 40

takeWater(15)
→ true

currentWater
→ 25
```

Если попытаться забрать:

```text
30
```

при остатке:

```text
25
```

операция должна завершиться неуспешно, а состояние бака не должно измениться.

---

## Важное требование

Не переносите:

```text
capacity
currentWater
```

в `PlantBed`.

Грядка отвечает за состояние почвы.

Бак отвечает за запас воды.

Это две разные ответственности.

# 3. Сервис полива координирует объекты

Теперь нужно выполнить сценарий:

```text
выбрать грядку
↓
определить количество воды
↓
проверить бак
↓
забрать воду
↓
полить грядку
```

Не помещайте весь этот сценарий в:

```text
PlantBed
```

и не помещайте его в:

```text
WaterTank
```

Создайте отдельный класс:

```java
IrrigationService
```

Пока используйте простое правило:

```text
если moisture < 30
→ нужно 4 литра

если 30 <= moisture < 50
→ нужно 2 литра

если moisture >= 50
→ полив не нужен
```

Добавьте в `IrrigationService` операцию по смыслу:

```java
boolean irrigate(PlantBed bed)
```

Точную сигнатуру можно выбрать самостоятельно.

`IrrigationService` должен использовать объект `WaterTank`.

Передайте зависимость через конструктор.

Например по смыслу:

```java
WaterTank tank = new WaterTank(...);

IrrigationService service =
        new IrrigationService(tank);
```

---

## Правила выполнения

Полив считается успешным, если:

- грядке действительно нужна вода;
- в баке достаточно воды;
- вода успешно списана;
- состояние грядки успешно изменено.

При невозможности полива система не должна оставаться в частично изменённом состоянии.

Например, нельзя получить:

```text
вода из бака уже списана
↓
грядка не была полита
```

---

## Пример 1

До:

```text
грядка:
moisture = 20

бак:
currentWater = 10
```

Нужно:

```text
4 литра
```

После:

```text
moisture = 60
currentWater = 6
```

---

## Пример 2

До:

```text
грядка:
moisture = 20

бак:
currentWater = 3
```

После попытки полива:

```text
moisture = 20
currentWater = 3
```

Полив не выполнен.

---

## После этапа

Сформулируйте одним предложением ответственность каждого класса:

```text
PlantBed
→ ?

WaterTank
→ ?

IrrigationService
→ ?
```

Эти ответы должны быть понятны без чтения кода.

# 4. Несколько грядок

В теплице теперь несколько грядок.

Создайте класс:

```java
Greenhouse
```

Он хранит обычный массив:

```java
PlantBed[]
```

Внешний код не должен сам:

```text
перебирать массив
↓
сравнивать id
↓
работать с индексами
```

только для того, чтобы найти нужную грядку.

`Greenhouse` должен предоставлять операцию:

```text
найти грядку по id
```

Точную сигнатуру придумайте самостоятельно.

Если грядка не найдена, метод может вернуть:

```java
null
```

---

## Пример

Есть:

```text
B-101 → Tomatoes
B-102 → Cucumbers
B-103 → Peppers
```

Запрос:

```text
B-102
```

Результат:

```text
PlantBed для Cucumbers
```

Запрос:

```text
B-999
```

Результат:

```text
null
```

---

## Использование

Теперь основной сценарий должен выглядеть по смыслу так:

```text
попросить Greenhouse найти грядку
↓
если грядка существует
↓
передать её IrrigationService
```

Детали хранения массива должны оставаться внутри `Greenhouse`.

# 5. Правила полива меняются

До сих пор `IrrigationService` сам решал:

```text
сколько литров нужно грядке
```

Но агрономы используют разные режимы полива.

Нужно поддержать два режима.

---

## Обычный режим

Правила:

```text
moisture < 30
→ 4 литра

30 <= moisture < 50
→ 2 литра

moisture >= 50
→ 0 литров
```

---

## Экономный режим

Правила:

```text
moisture < 20
→ 3 литра

20 <= moisture < 40
→ 1 литр

moisture >= 40
→ 0 литров
```

---

## Проблема

Не добавляйте в `IrrigationService`:

```java
if (mode.equals("regular")) {
    ...
} else if (mode.equals("economy")) {
    ...
}
```

`IrrigationService` не должен знать детали всех существующих режимов.

Ему нужно только одно поведение:

> определить, сколько воды требуется конкретной грядке.

---

## Задача

Создайте интерфейс, описывающий этот контракт.

Название придумайте самостоятельно.

Например по смыслу он должен предоставлять операцию:

```text
получить количество воды
для указанной грядки
```

Создайте две реализации:

```text
обычный режим
экономный режим
```

`IrrigationService` должен зависеть от интерфейса, а не от конкретной реализации.

Передайте реализацию через конструктор.

По смыслу:

```java
IrrigationService(
    WaterTank tank,
    SomeWateringContract policy
)
```

Конкретные имена придумайте самостоятельно.

---

## Проверка архитектуры

Должно быть возможно заменить:

```text
обычный режим
```

на:

```text
экономный режим
```

без изменения кода самого `IrrigationService`.

# 6. Делегирование

После предыдущего этапа `IrrigationService` не должен самостоятельно вычислять количество воды.

Он должен попросить другой объект:

```text
Сколько воды требуется этой грядке?
```

То есть:

```text
IrrigationService
↓ делегирует расчёт
объекту правила полива
```

После получения количества воды сервис:

```text
проверяет возможность выполнения
↓
просит WaterTank выдать воду
↓
просит PlantBed изменить влажность
```

Проверьте, что каждый объект выполняет только свою часть работы.

# 9. Обязательные проверки

## Грядка

### Нижняя граница

```text
moisture = 0
```

Объект остаётся корректным.

### Верхняя граница

```text
moisture = 100
```

Объект остаётся корректным.

### Недопустимый полив

```text
water(0)
water(-1)
```

Состояние не меняется.

### Переполнение влажности

Если операция привела бы к:

```text
moisture > 100
```

инвариант:

```text
0 <= moisture <= 100
```

не должен нарушаться.

---

## Бак

Проверьте:

```text
takeWater(0)
takeWater(-1)
```

```text
takeWater(amount > currentWater)
```

```text
refill(amount <= 0)
```

```text
refill(amount),
если результат превысит capacity
```

Ни одна операция не должна нарушать:

```text
0 <= currentWater <= capacity
```

---

## Сервис

Проверьте:

```text
полив нужен + воды хватает
```

```text
полив нужен + воды не хватает
```

```text
полив не нужен
```

---

## Поиск

Проверьте:

```text
существующий id
```

и:

```text
несуществующий id
```

---

# 10. Требования к дизайну

Перед сдачей проверьте следующие пункты.

## Инкапсуляция

Нельзя напрямую изменить:

```text
moisture
currentWater
capacity
```

в обход правил объекта.

---

## Инварианты

После любой публичной операции должны выполняться:

```text
PlantBed:
0 <= moisture <= 100
```

```text
WaterTank:
0 <= currentWater <= capacity
```

---

## Ответственность

Не должно быть класса, который одновременно:

```text
хранит грядки
+
управляет водой
+
считает режим полива
+
сам меняет все состояния
```

---

## Композиция

Связи между объектами выражаются через поля объектных типов там, где один объект использует другой.

---

## Делегирование

`IrrigationService` не должен самостоятельно выполнять работу:

```text
WaterTank
```

или:

```text
правила полива
```

Он координирует их.

---

## Интерфейс

`IrrigationService` должен зависеть от контракта правила полива.

Плохо:

```java
private RegularWateringPolicy policy;
```

если сервису достаточно общего поведения.

Нужно зависеть от интерфейса.

---

## `main()`

`main()` не должен содержать всю бизнес-логику системы.

По смыслу он должен:

```text
создать объекты
↓
связать их
↓
запустить сценарий
↓
показать результат
```
