# 1. Ориентация в IDE

## Что такое проект

В IntelliJ IDEA мы обычно работаем не с одним отдельным `.java`-файлом, а с **проектом**.

Проект объединяет:

- исходные файлы;
- настройки;
- используемый JDK;
- конфигурации запуска;
- позже — тесты, зависимости и настройки системы сборки.

Простейший учебный проект может выглядеть так:

```text
java-week-1
└── src
    └── Main.java
```

В `Main.java` находится Java-код:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

Базовая модель:

```text
проект
├── файлы
├── код
├── JDK
└── конфигурация запуска
```

---

## Как открыть существующий проект

На стартовом экране IntelliJ IDEA выберите:

```text
Open
```

и укажите **папку проекта**.

Если другой проект уже открыт:

```text
File
↓
Open
```

Например, если структура такая:

```text
projects
└── java-week-1
    └── src
        └── Main.java
```

открывать нужно:

```text
java-week-1
```

а не только:

```text
Main.java
```

IDE должна видеть проект целиком.

---

## Основные области IntelliJ IDEA

Упрощённо окно IDE можно представить так:

```text
┌───────────────────────────────────────────────────┐
│                 верхняя панель                    │
├──────────────┬────────────────────────────────────┤
│              │                                    │
│   Project    │              Editor                │
│              │                                    │
│ файлы        │           исходный код             │
│ проекта      │                                    │
│              │                                    │
├──────────────┴────────────────────────────────────┤
│         Run / Terminal / другие Tool Windows      │
└───────────────────────────────────────────────────┘
```

На первых неделях особенно важны:

```text
Project
→ файлы проекта

Editor
→ код

Run
→ результат выполнения программы

Terminal
→ командная строка
```

---

## Окно `Project`

`Project` показывает структуру проекта:

```text
java-week-1
└── src
    └── Main.java
```

Через него можно:

- открывать файлы;
- создавать новые файлы;
- создавать Java-классы;
- создавать директории;
- переименовывать элементы;
- удалять элементы;
- перемещаться по структуре проекта.

Если окно случайно закрыто:

```text
View
↓
Tool Windows
↓
Project
```

Главная идея:

```text
Project
→ навигация по файлам проекта
```

---

## Где находятся исходные файлы

В нашем простом учебном проекте Java-файлы находятся в:

```text
src
```

Например:

```text
src
├── Main.java
├── Calculator.java
└── Example.java
```

Файлы:

```text
.java
```

содержат исходный код, который пишет разработчик.

Не путайте:

```text
Main.java
→ исходный Java-код

Main.class
→ байткод после компиляции
```

В редакторе мы почти всегда работаем именно с `.java`-файлами.

---

## Editor

После открытия файла его содержимое появляется в центральной части IDE — редакторе.

Например:

```java
public class Main {

    public static void main(String[] args) {
        int age = 18;
        System.out.println(age);
    }
}
```

Здесь мы:

- пишем код;
- читаем его;
- изменяем;
- исправляем ошибки;
- используем подсказки IDE.

---

## Вкладки

Несколько открытых файлов отображаются как вкладки:

```text
Main.java | Calculator.java | Example.java
```

Можно быстро переключаться между ними.

Важно:

```text
закрыть вкладку
≠
удалить файл
```

Если вы закрыли вкладку, файл всё равно остаётся в проекте и его можно снова открыть через `Project`.

---

## Tool Windows

`Project`, `Run`, `Terminal` и другие панели называются **Tool Windows**.

Если нужная панель пропала:

```text
View
↓
Tool Windows
↓
нужное окно
```

Поэтому закрыть какую-либо панель случайно не страшно.

---

## Где посмотреть JDK проекта

Для компиляции и запуска Java-кода проекту нужен JDK.

Открыть настройки проекта можно через:

```text
File
↓
Project Structure
```

В разделе проекта можно посмотреть выбранный SDK/JDK.

Например:

```text
Project SDK
→ JDK 21
```

или другую версию, которая используется на курсе.

Главная модель:

```text
IntelliJ IDEA
↓
использует JDK
↓
компилирует и запускает Java-код
```

IDE и JDK — не одно и то же:

```text
IntelliJ IDEA
→ среда разработки

JDK
→ набор Java-инструментов
```

# 2. Базовая работа с редактором

## Создание Java-файла

Новый Java-класс можно создать через окно `Project`.

Обычно:

```text
правый клик по src
↓
New
↓
Java Class
```

Введите имя:

```text
Main
```

и IDE создаст Java-файл.

В дальнейшем появятся пакеты и более сложная структура проекта, но пока достаточно работать внутри `src`.

---

## Обычный цикл редактирования

Работа с кодом почти всегда выглядит так:

```text
написали код
↓
изменили код
↓
запустили
↓
посмотрели результат
↓
снова изменили
```

Не нужно пытаться сразу написать программу полностью и без ошибок.

Разработка — итеративный процесс.

---

## Работа со строками

При редактировании кода постоянно приходится:

- копировать строки;
- удалять строки;
- перемещать строки вверх и вниз;
- дублировать фрагменты;
- выделять несколько строк;
- отменять изменения.

Не обязательно запоминать сочетания клавиш для всех действий.

Если вы не знаете, как выполнить действие:

```text
Search Everywhere
или
Find Action
```

и вводите название:

```text
Duplicate Line
Move Line
Delete Line
Reformat Code
```

---

## Комментарии

Однострочный комментарий:

```java
// эта строка не выполняется
int age = 18;
```

Можно временно закомментировать код:

```java
// System.out.println(age);
```

IDE умеет комментировать и раскомментировать выделенные строки.

Это удобно при экспериментах:

```java
int age = 18;

// System.out.println("old");
System.out.println(age);
```

Но не стоит оставлять большие куски ненужного закомментированного кода в готовом решении.

---

## Undo и Redo

Если вы сделали неудачное изменение:

```text
Undo
→ отменить последнее действие
```

Если отменили лишнее:

```text
Redo
→ вернуть отменённое изменение
```

Это одна из самых важных привычек при работе с редактором.

Не бойтесь экспериментировать:

```text
изменили
↓
не понравилось
↓
Undo
```

---

## Форматирование кода

Java-код должен быть не только правильным, но и читаемым.

Например:

```java
if(age>=18){System.out.println("OK");}
```

работает, но читается плохо.

После форматирования:

```java
if (age >= 18) {
    System.out.println("OK");
}
```

IntelliJ IDEA умеет автоматически приводить код к настроенному стилю.

Используйте действие:

```text
Reformat Code
```

Главная идея:

```text
не выравниваем код вручную пробелами
↓
используем форматирование IDE
```

---

## Что исправляет форматирование

Обычно `Reformat Code` приводит в порядок:

- отступы;
- пробелы;
- переносы;
- оформление блоков;
- расположение некоторых конструкций.

Например:

```java
for(int i=0;i<10;i++){
System.out.println(i);
}
```

становится:

```java
for (int i = 0; i < 10; i++) {
    System.out.println(i);
}
```

Форматирование **не исправляет алгоритм**.

Если код:

```java
int total = price + count;
```

должен был умножать цену на количество, `Reformat Code` этого не заметит.

# 3. Автодополнение

## Зачем нужно автодополнение

В Java существует огромное количество классов и методов.

Разработчик не обязан помнить точное имя всего API.

IDE помогает продолжить ввод.

Например, начинаем писать:

```java
System.out.
```

IntelliJ IDEA показывает доступные варианты:

```text
print
println
printf
...
```

Вы выбираете нужный вариант, и IDE дописывает его.

---

## Подсказки для переменных

Если объявлено:

```java
int totalPrice = 500;
```

и позже вы начинаете вводить:

```text
tot
```

IDE может предложить:

```text
totalPrice
```

Это особенно полезно, когда имена становятся длиннее:

```java
int totalPriceWithDelivery = 700;
```

---

## Подсказки для методов

Например:

```java
System.out.pr
```

может быть продолжено до:

```java
System.out.println();
```

На следующих неделях это станет особенно важно, когда появятся объекты:

```java
text.
```

После точки IDE показывает методы, доступные для этого объекта.

---

## Подсказки параметров

Методы могут принимать параметры.

Например:

```java
System.out.println(...)
```

IDE помогает понять, что нужно передать внутрь скобок.

В более сложных методах подсказки параметров особенно полезны.

Главная идея:

```text
метод
↓
IDE показывает возможные аргументы
↓
разработчик выбирает подходящие
```

---

## Автодополнение не заменяет понимание

Плохой подход:

```text
нажимать первый вариант,
не понимая, что он делает
```

Правильный:

```text
вижу предложение
↓
читаю имя
↓
понимаю, подходит ли оно
↓
выбираю
```

IDE помогает писать быстрее, но решение по-прежнему принимает разработчик.

---

# 4. Live Templates

## Что такое Live Template

Live Template — это короткое сокращение, которое IDE разворачивает в типовой фрагмент кода.

Например:

```text
sout
```

может быть развёрнуто в:

```java
System.out.println();
```

Вместо того чтобы каждый раз писать длинную конструкцию вручную.

---

## Пример с `sout`

Введите:

```text
sout
```

и примените предложенный шаблон.

Получится:

```java
System.out.println();
```

После этого останется добавить значение:

```java
System.out.println("Hello");
```

---

## Шаблоны циклов

Для типовых циклов также существуют шаблоны.

Например, IDE может помочь быстро получить каркас:

```java
for (int i = 0; i < 10; i++) {

}
```

Затем вы изменяете:

- начальное значение;
- условие;
- шаг;
- тело цикла.

Главная идея:

```text
Live Template
↓
создаёт каркас
↓
вы заполняете нужные части
```

---

## Что важно запомнить

Не нужно учить десятки сокращений наизусть.

На первой неделе достаточно:

```text
sout
→ вывод

шаблон цикла
→ быстро создать каркас for
```

Со временем часто используемые шаблоны запоминаются сами.

---

## Где посмотреть доступные шаблоны

Если хотите посмотреть список Live Templates, найдите настройки:

```text
Settings
↓
Editor
↓
Live Templates
```

Но на старте курса редактировать и создавать собственные шаблоны не требуется.

# 5. Ошибки, предупреждения и быстрые исправления

## IDE анализирует код во время написания

IntelliJ IDEA постоянно анализирует открытый файл.

Поэтому многие проблемы можно увидеть **ещё до запуска компилятора**.

Например:

```java
age = 18;
```

если `age` нигде не объявлена.

IDE подсветит проблему.

При компиляции `javac` тоже обнаружит такую ошибку.

Упрощённо:

```text
пишем код
↓
IDE анализирует его
↓
показывает проблему заранее
↓
при запуске компилятор всё равно проверяет код
```

---

## Красная подсветка

Красным обычно обозначаются ошибки, которые мешают корректной работе или компиляции кода.

Например:

```java
int age = "18";
```

Здесь строка:

```text
"18"
```

не может быть напрямую присвоена переменной типа:

```text
int
```

Другой пример:

```java
int age = 18
```

Пропущена:

```text
;
```

---

## Предупреждения

Не каждая проблема означает, что программа не скомпилируется.

IDE может показать предупреждение.

Например, переменная объявлена, но нигде не используется:

```java
int age = 18;
```

если далее `age` не встречается.

Программа может быть корректной, но IDE сообщает:

```text
возможно, здесь есть лишний или подозрительный код
```

---

## Ошибка и предупреждение — не одно и то же

Упрощённо:

```text
ошибка
→ код некорректен или не может быть выполнен как задумано

предупреждение
→ код может работать, но IDE видит потенциальную проблему
```

Не нужно пытаться любой ценой убрать каждое предупреждение.

Сначала прочитайте, что именно сообщает IDE.

---

## Как работать с подсветкой

Правильный процесс:

```text
вижу подчёркивание
↓
наводжу курсор / открываю описание
↓
читаю сообщение
↓
понимаю причину
↓
исправляю
```

Не стоит:

```text
вижу красное
↓
случайно меняю код
↓
надеюсь, что исчезнет
```

---

## Context Actions и `Alt+Enter`

Для многих ситуаций IntelliJ IDEA предлагает **Context Actions** — действия, подходящие к текущему месту в коде.

Обычно список можно открыть через:

```text
Alt+Enter
```

Например, IDE может предложить:

- исправить проблему;
- изменить тип;
- создать отсутствующий элемент;
- упростить конструкцию;
- применить рефакторинг.

---

## Quick Fix не нужно применять вслепую

Допустим, IDE предлагает изменение.

Перед применением спросите себя:

```text
Что изменится?
Почему IDE это предлагает?
Соответствует ли это моей задаче?
```

Главная привычка:

```text
Alt+Enter
≠
автоматически исправить всё

Alt+Enter
=
показать доступные варианты действий
```

---

## IDE не знает условие задачи

Например:

```java
int price = 500;
int count = 3;

int total = price + count;
```

IDE может не показать ошибку.

Код полностью корректен с точки зрения Java.

Но если по условию нужно:

```text
стоимость × количество
```

правильное выражение:

```java
int total = price * count;
```

Это логическая ошибка.

Поэтому:

```text
IDE
→ помогает проверять код

разработчик
→ проверяет алгоритм
```

---

# 6. Поиск и навигация

Когда проект становится больше одного файла, искать всё вручную через дерево проекта становится неудобно.

IntelliJ IDEA предоставляет несколько видов поиска.

---

## Поиск текста в текущем файле

Если нужно найти слово внутри открытого файла, используйте действие:

```text
Find
```

Например, хотим найти все появления:

```text
total
```

в `Main.java`.

IDE подсветит совпадения и позволит переходить между ними.

---

## Поиск текста по проекту

Иногда нужно найти текст во всех файлах проекта.

Например:

```text
Access denied
```

или:

```text
totalPrice
```

Для этого используется поиск по проекту.

Это обычный **текстовый поиск**.

Он просто ищет совпадающие символы.

---

## Search Everywhere

Один из самых полезных инструментов IntelliJ IDEA:

```text
Search Everywhere
```

Его можно открыть двойным нажатием:

```text
Shift
Shift
```

Через него можно искать:

- файлы;
- классы;
- символы;
- действия IDE;
- настройки.

Например:

```text
Main
```

может найти `Main.java`.

А:

```text
Reformat Code
```

может найти действие форматирования.

---

## Не знаете, где находится команда?

Не нужно долго искать по меню.

Откройте поиск и введите название действия:

```text
Reformat Code
Rename
Find Usages
Project Structure
```

Это очень полезная привычка:

```text
не знаю горячую клавишу
↓
не знаю пункт меню
↓
знаю название действия
↓
могу его найти
```

---

## Переход к объявлению

Допустим:

```java
int total = 100;

System.out.println(total);
```

Во второй строке используется переменная:

```text
total
```

IDE умеет перейти к месту, где она объявлена:

```java
int total = 100;
```

Позже это особенно пригодится для:

- методов;
- классов;
- полей;
- интерфейсов.

---

## Find Usages

Обратная задача:

> Где используется этот элемент?

Например:

```java
int age = 18;

System.out.println(age);

if (age >= 18) {
    System.out.println("Access granted");
}
```

Для переменной `age` можно выполнить:

```text
Find Usages
```

и увидеть места использования.

Это полезнее обычного поиска текста, потому что IDE понимает **структуру кода**.

---

## Поиск текста и Find Usages — разные вещи

Поиск текста:

```text
найти символы "age"
```

может найти:

- переменную `age`;
- слово внутри комментария;
- часть другой строки.

`Find Usages`:

```text
найти использования конкретной переменной age
```

То есть:

```text
текстовый поиск
→ ищет текст

Find Usages
→ ищет связи в коде
```

# 7. Безопасное переименование

## Почему ручное переименование опасно

Пусть есть код:

```java
int x = 18;

System.out.println(x);

if (x >= 18) {
    System.out.println("OK");
}
```

Мы решили заменить плохое имя:

```text
x
```

на:

```text
age
```

Если изменить только первую строку:

```java
int age = 18;

System.out.println(x);
```

код сломается.

---

## Rename Refactoring

IntelliJ IDEA умеет безопасно переименовывать элементы.

Выберите переменную и используйте:

```text
Rename
```

IDE обновит связанные использования:

```java
int age = 18;

System.out.println(age);

if (age >= 18) {
    System.out.println("OK");
}
```

---

## Почему это не просто Find & Replace

Обычная текстовая замена:

```text
x → age
```

не понимает структуру программы.

Она может заменить лишний текст.

Например:

```java
int x = 10;
int max = 20;
```

Примитивная замена символа `x` может затронуть совсем не то, что нужно.

Refactoring понимает:

```text
мы переименовываем конкретную переменную
```

Главная идея:

```text
Rename
→ работа со структурой программы

Replace
→ работа с текстом
```

---

## Когда использовать Rename

Не только для локальных переменных.

Позже через Rename будем переименовывать:

- методы;
- классы;
- поля;
- параметры;
- файлы и другие элементы.

Полезная привычка:

```text
хочу изменить имя элемента программы
↓
сначала думаю про Rename
```

---

# 8. Запуск программы

## Где запускается `main`

Для Java-программы с:

```java
public static void main(String[] args) {
    System.out.println("Hello");
}
```

IntelliJ IDEA показывает возможность запуска рядом с `main` или классом.

Нажмите:

```text
Run
```

IDE:

```text
собирает / компилирует код
↓
запускает Java-программу
↓
открывает Run
↓
показывает результат
```

---

## Окно `Run`

Для программы:

```java
System.out.println("Hello, Java!");
```

в `Run` появится:

```text
Hello, Java!
```

Также там можно увидеть информацию о завершении процесса.

Например:

```text
Process finished with exit code 0
```

Это означает, что процесс завершился успешно.

Но снова:

```text
программа завершилась успешно
≠
алгоритм дал правильный ответ
```

---

## Повторный запуск

Рабочий цикл:

```text
написали код
↓
Run
↓
увидели результат
↓
изменили код
↓
Run снова
```

Например:

```java
int a = 5;
int b = 3;

System.out.println(a + b);
```

Результат:

```text
8
```

Меняем:

```java
System.out.println(a * b);
```

Запускаем снова:

```text
15
```

---

## Stop

Если программа долго работает или попала в бесконечный цикл, её можно остановить:

```text
Stop
```

Например, ошибочный цикл:

```java
int i = 0;

while (i < 10) {
    System.out.println(i);
}
```

`i` не меняется.

Поэтому условие:

```java
i < 10
```

всегда остаётся истинным.

Программа продолжит работать, пока её не остановить.

---

## Run Configuration

Чтобы запустить программу, IDE должна знать:

- какой класс запускать;
- где находится `main`;
- какой JDK использовать;
- какие параметры передавать программе.

Эти настройки объединяются в:

```text
Run Configuration
```

На первом занятии достаточно модели:

```text
Run Configuration
→ описание того, что и как запускать
```

Обычно для простого `main` IntelliJ IDEA создаёт подходящую конфигурацию автоматически.

---

## Не углубляемся в настройки запуска

Позже Run Configuration может содержать:

- program arguments;
- VM options;
- environment variables;
- рабочую директорию.

Но на первой неделе это пока не требуется.

# 9. Встроенный Terminal

## Зачем терминал внутри IDE

IntelliJ IDEA содержит встроенный терминал.

Он позволяет выполнять команды, не переключаясь в отдельное приложение.

Открыть:

```text
View
↓
Tool Windows
↓
Terminal
```

Упрощённо:

```text
Editor
→ работаем с кодом

Terminal
→ выполняем команды
```

---

## Проверяем Java

В терминале выполните:

```bash
java -version
```

Команда показывает информацию о Java runtime.

Затем:

```bash
javac -version
```

Эта команда показывает версию компилятора.

Если проект настроен на JDK, IntelliJ IDEA может делать его доступным во встроенном терминале.

---

## Связь с первой лекцией

На лекции была схема:

```text
Main.java
↓
javac
↓
Main.class
↓
JVM
↓
выполнение
```

IDE обычно скрывает эти действия за кнопкой:

```text
Run
```

Но их можно выполнить вручную.

---

## Ручная компиляция

Пусть есть:

```text
Main.java
```

с кодом:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
```

В директории, где находится файл, можно выполнить:

```bash
javac Main.java
```

Если компиляция успешна, появится:

```text
Main.class
```

---

## Ручной запуск

После компиляции:

```bash
java Main
```

Результат:

```text
Hello
```

Обратите внимание:

```bash
java Main
```

а не:

```bash
java Main.class
```

Команде `java` передаётся имя класса.

---

## Если терминал открыт не в той директории

Команды работают относительно текущей директории.

Поэтому важно понимать, где сейчас находится терминал.

Структура:

```text
java-week-1
└── src
    └── Main.java
```

Если `Main.java` находится внутри `src`, для ручной компиляции нужно либо перейти в эту директорию, либо правильно указать путь.

На первом семинаре достаточно понять сам принцип.

---

## IDE Run и терминал

Сравним:

```text
Run в IDE
↓
IDE сама организует компиляцию и запуск
```

и:

```text
Terminal

javac Main.java
↓
java Main
```

Это не два разных способа выполнения Java.

IDE просто автоматизирует работу с теми же Java-инструментами.

# 10. Undo и Local History

## Undo — первая линия защиты

Если вы только что сломали код:

```text
Undo
```

обычно достаточно.

Например:

было:

```java
int total = price * count;
```

случайно удалили:

```java
int total =
```

Используем Undo и возвращаем изменение.

---

## Но что если изменений было много?

Иногда нужно вернуть состояние файла, которое было несколько минут назад.

Или:

- вы удалили большой фрагмент;
- несколько раз закрывали и открывали файл;
- сделали много изменений;
- обычного Undo уже неудобно использовать.

В таких ситуациях может помочь:

```text
Local History
```

---

## Что такое Local History

IntelliJ IDEA локально хранит историю изменений файлов проекта.

Это позволяет:

- посмотреть предыдущие состояния;
- сравнить версии;
- вернуть удалённый фрагмент;
- восстановить файл;
- откатить неудачные изменения.

Для файла или директории можно открыть:

```text
Local History
↓
Show History
```

Название пункта может немного отличаться в зависимости от контекста и версии IDE.

---

## Пример использования

Было:

```java
int price = 500;
int count = 3;

int total = price * count;

System.out.println(total);
```

После нескольких изменений код стал:

```java
System.out.println("test");
```

Вы понимаете, что хотите вернуть старую версию.

Открываете Local History и находите предыдущее состояние файла.

IDE позволяет сравнить:

```text
текущая версия
↔
предыдущая версия
```

и восстановить нужные изменения.

---

## Local History не заменяет Git

Важно различать:

```text
Local History
→ локальная страховка внутри IDE

Git
→ полноценная система контроля версий
```

Local History полезен, когда:

```text
случайно удалил код
```

Git нужен для:

- истории проекта;
- командной работы;
- сдачи домашних заданий;
- веток;
- обмена кодом.

Git будет разобран отдельно.

---

## Полезная привычка

```text
только что сломал
→ Undo

не понимаю, когда сломал
→ Local History

нужна полноценная история проекта
→ Git
```

# Результат

После самостоятельного повторения вы должны уметь:

- открыть существующий Java-проект;
- найти исходные файлы;
- ориентироваться в `Project`, `Editor`, `Run` и `Terminal`;
- проверить JDK проекта;
- создать Java-класс;
- редактировать и форматировать код;
- использовать автодополнение;
- использовать базовые Live Templates;
- отличать ошибку от предупреждения;
- читать сообщения IDE;
- открывать Context Actions;
- использовать Quick Fix осознанно;
- искать файлы и действия;
- переходить по коду;
- находить использования;
- безопасно переименовывать переменные;
- запускать, перезапускать и останавливать программу;
- использовать встроенный терминал;
- запускать `java` и `javac`;
- отменять изменения;
- находить предыдущие состояния через Local History.

Главная идея всего занятия:

```text
я пишу код
↓
IDE помогает писать быстрее
↓
IDE помогает заметить проблему
↓
я читаю и понимаю сообщение
↓
я безопасно изменяю код
↓
я запускаю программу
↓
проверяю результат
↓
не боюсь экспериментировать
```

IntelliJ IDEA — не «магия, которая пишет программу за нас».

Это инструмент, который помогает разработчику быстрее выполнять рутинные действия и лучше ориентироваться в коде.
