# Сквозной проект: сервис аренды оборудования

Компания сдаёт оборудование в аренду.

В каталоге есть:

```text
Laptop
Camera
Bicycle
```

У каждого предмета есть общие данные:

```text
inventoryCode
name
dailyRate
```

Но стоимость аренды и дополнительные правила зависят от конкретного типа оборудования.

К концу работы должна получиться система, в которой:

- разные виды оборудования имеют общий базовый тип;
- общий тип нельзя создать напрямую;
- стоимость аренды вычисляется полиморфно;
- разные объекты можно хранить в одном массиве;
- для части оборудования существует отдельный контракт залога;
- заказ аренды содержит клиента и выбранное оборудование;
- клиент имеет корректные `equals()`, `hashCode()` и `toString()`;
- основной алгоритм не содержит длинных ветвлений по конкретным типам.

# Этап 1. Общая модель оборудования

В каталоге есть три типа оборудования:

```text
Laptop
Camera
Bicycle
```

Для любого предмета известны:

```text
inventoryCode
name
dailyRate
```

Кроме общих данных, у типов есть свои характеристики:

```text
Laptop
→ ramGb

Camera
→ megapixels

Bicycle
→ electric
```

Постройте модель так, чтобы общие данные не дублировались между тремя классами.

Общий тип оборудования должен:

- хранить общие поля;
- самостоятельно инициализировать свою часть объекта;
- сохранять состояние инкапсулированным;
- предоставлять доступ к данным через публичные методы, когда это необходимо.

Конкретные типы должны хранить только свои дополнительные данные.

### Пример создания объектов

```java
Laptop laptop =
        new Laptop(
                "L-101",
                "ThinkBook",
                1500,
                16
        );

Camera camera =
        new Camera(
                "C-205",
                "Sony Alpha",
                2000,
                24
        );

Bicycle bicycle =
        new Bicycle(
                "B-330",
                "City Bike",
                700,
                false
        );
```

### Проверьте

После создания объектов должны быть доступны:

```text
общие данные предмета
+
специфические данные конкретного типа
```

При этом общие поля не должны повторяться в наследниках.

# Этап 2. Разная стоимость аренды

Стоимость аренды зависит от типа оборудования.

## `Laptop`

Стоимость:

```text
dailyRate * days
```

## `Camera`

К стоимости аренды один раз добавляется сервисный сбор:

```text
500
```

Итого:

```text
dailyRate * days + 500
```

## `Bicycle`

Для обычного велосипеда:

```text
dailyRate * days
```

Для электрического:

```text
dailyRate * days + 300 * days
```

У любого оборудования должна существовать одна общая операция:

```java
calculateRentalCost(int days)
```

Но общей формулы для всех типов нет.

Измените модель так, чтобы:

- общий тип оборудования отражал это ограничение;
- нельзя было создать объект «просто оборудование»;
- каждый конкретный тип самостоятельно реализовывал расчёт своей стоимости;
- для переопределённых методов использовался `@Override`.

### Пример 1

```text
Входные данные:

Laptop
dailyRate = 1500
days = 3

Результат:

4500
```

### Пример 2

```text
Входные данные:

Camera
dailyRate = 2000
days = 3

Результат:

6500
```

### Пример 3

```text
Входные данные:

электрический Bicycle
dailyRate = 700
days = 3

Результат:

3000
```

# Этап 3. Один алгоритм для разных типов

Теперь сервис должен уметь работать сразу с несколькими предметами.

Создайте массив общего типа и поместите в него разные объекты:

```text
Laptop
Camera
Bicycle
```

Напишите обработку, которая для заданного количества дней:

1. выводит стоимость аренды каждого предмета;
2. считает общую стоимость аренды;
3. находит самый дорогой предмет по стоимости аренды;
4. считает количество предметов, аренда которых стоит не меньше заданного порога.

Основной алгоритм должен работать через общий тип.

### Пример

```text
Входные данные:

days = 3
threshold = 4000

Laptop("L-101", "ThinkBook", 1500, 16)
Camera("C-205", "Sony Alpha", 2000, 24)
Bicycle("B-330", "City Bike", 700, false)
```

Стоимость:

```text
Laptop: 4500
Camera: 6500
Bicycle: 2100
```

Результат:

```text
Total: 13100
Most expensive: Sony Alpha
At least 4000: 2
```

### Ограничение

В основном алгоритме нельзя вычислять стоимость так:

```text
если Laptop
→ одна формула

если Camera
→ другая формула

если Bicycle
→ третья формула
```

Используйте полиморфный вызов общей операции.

# Этап 4. Залог не для всех предметов

Компания требует залог только для части оборудования.

Залог нужен для:

```text
Laptop
Camera
```

Для:

```text
Bicycle
```

залога нет.

Правила:

```text
Laptop
→ 20000

Camera
→ 15000
```

Добавьте отдельный контракт для объектов, для которых требуется залог.

Контракт должен позволять получить размер залога.

Измените систему так, чтобы:

- `Laptop` поддерживал этот контракт;
- `Camera` поддерживал этот контракт;
- `Bicycle` не был обязан реализовывать операцию залога;
- программа могла пройти по общему массиву оборудования и посчитать сумму всех необходимых залогов.

### Пример

Для массива:

```text
Laptop
Camera
Bicycle
```

результат:

```text
Total deposit: 35000
```

### Важное ограничение

Не добавляйте в общий класс оборудования фиктивный метод:

```text
calculateDeposit()
→ 0
```

только ради `Bicycle`.

Если возможность относится не ко всем наследникам, она не должна искусственно становиться обязательной для всей иерархии.

# Этап 5. Заказ аренды и композиция




# Этап 6. Равенство клиентов

В системе могут появиться два разных объекта `Customer`, которые описывают одного и того же клиента.

Например:

```java
Customer first =
        new Customer(
                42,
                "Anna",
                "anna@example.com"
        );

Customer second =
        new Customer(
                42,
                "Anna Petrova",
                "new-email@example.com"
        );
```

По бизнес-правилу клиент определяется по:

```text
id
```

Поэтому эти два объекта должны считаться равными.

Для `Customer` переопределите:

```java
equals(...)
hashCode()
toString()
```

Правила:

```text
одинаковый id
→ equals() == true
```

и обязательно:

```text
equals() == true
↓
одинаковый hashCode
```

### Пример 1

```text
first.id = 42
second.id = 42

first == second
→ false

first.equals(second)
→ true

first.hashCode() == second.hashCode()
→ true
```

### Пример 2

```text
first.id = 42
second.id = 77

first.equals(second)
→ false
```

Дополнительно выведите:

```java
first.getClass()
```

и результат:

```java
first.toString()
```

Будьте готовы объяснить:

- почему базовый класс сделан абстрактным;
