# 1. Наследование, `super` и инкапсуляция

## Задача 1. Каталог библиотеки

**Обязательная**

**Ориентировочное время:** 10 минут

В библиотечной системе отдельно реализованы книги и журналы.

Исходный код:

```java
class Book {
    private String inventoryNumber;
    private String title;
    private String author;

    public Book(
            String inventoryNumber,
            String title,
            String author
    ) {
        this.inventoryNumber = inventoryNumber;
        this.title = title;
        this.author = author;
    }

    public void printInfo() {
        System.out.println(
                inventoryNumber + ": " + title
        );
        System.out.println(
                "Author: " + author
        );
    }
}

```

```java
class Magazine {
    private String inventoryNumber;
    private String title;
    private int issueNumber;

    public Magazine(
            String inventoryNumber,
            String title,
            int issueNumber
    ) {
        this.inventoryNumber = inventoryNumber;
        this.title = title;
        this.issueNumber = issueNumber;
    }

    public void printInfo() {
        System.out.println(
                inventoryNumber + ": " + title
        );
        System.out.println(
                "Issue: " + issueNumber
        );
    }
}

```

Код работает, но общая часть двух типов дублируется.

Перестрой модель так, чтобы:

- появился общий тип для единицы библиотечного каталога;
- книга и журнал были его разновидностями;
- `inventoryNumber` и `title` хранились только в общей части;
- эти поля оставались `private`;
- каждый конкретный тип сохранял собственные данные;
- конструкторы наследников корректно инициализировали общую часть;
- общий фрагмент `printInfo()` не дублировался.

### Пример 1

```text
Входные данные:
Book
inventoryNumber = "B-104"
title = "Clean Code"
author = "Robert Martin"

Результат:
B-104: Clean Code
Author: Robert Martin

```

### Пример 2

```text
Входные данные:
Magazine
inventoryNumber = "M-027"
title = "Java Monthly"
issueNumber = 12

Результат:
M-027: Java Monthly
Issue: 12

```

### Ограничение

Не дублируй `inventoryNumber` и `title` в классах-наследниках.

Поля общего класса должны оставаться `private`.

# 2. Полиморфизм, `abstract` и массив общего типа

## Задача 2. Билеты на мероприятие

**Обязательная**

**Ориентировочное время:** 15 минут

Система продажи билетов поддерживает:

```text
RegularTicket
VipTicket
ChildTicket

```

Для любого билета известны:

- `eventName`;
- `basePrice`.

Но итоговая стоимость рассчитывается по-разному:

```text
RegularTicket
→ basePrice

VipTicket
→ basePrice + 2000

ChildTicket
→ basePrice / 2

```

В предметной области не существует «просто билета» без конкретного тарифа.

Построй модель так, чтобы:

- был общий тип для всех билетов;
- объект общего типа нельзя было создать напрямую;
- общие данные хранились в базовом классе;
- операция вычисления итоговой стоимости была общей по смыслу, но не имела общей реализации;
- `RegularTicket`, `VipTicket` и `ChildTicket` самостоятельно определяли её реализацию;
- объекты разных видов можно было хранить в одном массиве;
- один цикл вычислял стоимость всех билетов.

После этого программа должна определить:

- общую стоимость всех билетов;
- самый дорогой билет;
- количество билетов стоимостью не меньше `3000`.

### Пример 1

```text
Входные данные:
RegularTicket("Concert", 2500)
VipTicket("Concert", 2500)
ChildTicket("Concert", 2500)

Результат:
2500
4500
1250
Total: 8250
Most expensive: 4500
At least 3000: 1

```

### Пример 2

```text
Входные данные:
RegularTicket("Show", 4000)
VipTicket("Show", 4000)

Результат:
4000
6000
Total: 10000
Most expensive: 6000
At least 3000: 2

```

### Ограничение

В основном цикле нельзя определять цену через проверку конкретного типа:

```text
если RegularTicket ...
если VipTicket ...
если ChildTicket ...

```

Цена должна вычисляться полиморфно.

# 3. `instanceof`, приведение и специфическое поведение

## Задача 3. Игровые персонажи

**Обязательная**

**Ориентировочное время:** 10 минут

В игре есть общий тип:

```text
GameCharacter

```

и два конкретных персонажа:

```text
Warrior
Mage

```

У любого персонажа есть:

```java
attack()

```

и эта операция должна работать полиморфно.

Только у `Mage` есть дополнительная операция:

```java
restoreMana()

```

Создай массив:

```java
GameCharacter[]

```

с несколькими воинами и магами.

Программа должна:

1. одним циклом вызвать `attack()` у каждого персонажа;
2. посчитать общее количество персонажей;
3. посчитать количество магов;
4. только у магов дополнительно вызвать `restoreMana()`.

### Пример

```text
Входные данные:
Warrior("Arthas")
Mage("Jaina")
Warrior("Grom")

Результат:
Arthas attacks with a sword
Jaina casts a spell
Jaina restores mana
Grom attacks with a sword
Characters: 3
Mages: 1

```

### Ограничение

`instanceof` разрешён только для действия, которое существует исключительно у `Mage`.

Выбор реализации `attack()` через `instanceof` запрещён.

# 4. `Object`, `equals()` и `hashCode()`

## Задача 4. Запись на курс

**Обязательная**

**Ориентировочное время:** 15 минут

Класс:

```text
CourseEnrollment

```

описывает запись студента на учебный курс.

У объекта есть:

- `studentId`;
- `courseCode`;
- `semester`.

Две записи считаются равными, если совпадают **все три поля**.

Реализуй:

```java
equals(...)
hashCode()
toString()

```

После этого создай несколько объектов и проверь:

- `==`;
- `equals()`;
- совпадение `hashCode()` для равных объектов;
- `getClass()`;
- `toString()`.

### Пример 1

```text
Входные данные:
first =
CourseEnrollment(101, "JAVA-1", "2026-FALL")

second =
CourseEnrollment(101, "JAVA-1", "2026-FALL")

Результат:
first == second: false
first.equals(second): true
hashCode equal: true
class: CourseEnrollment

```

### Пример 2

```text
Входные данные:
first =
CourseEnrollment(101, "JAVA-1", "2026-FALL")

second =
CourseEnrollment(101, "JAVA-1", "2027-SPRING")

Результат:
first.equals(second): false

```

### Дополнительно

Создай:

```java
CourseEnrollment third = first;

```

и сравни:

```text
first == third
first.equals(third)

```

### Ограничения

Все поля, участвующие в `equals()`, должны участвовать и в `hashCode()`.

## Задача 6. Убери проверки типов

**Дополнительная**

**Ориентировочное время:** 15 минут

Дан фрагмент программы:

```java
for (Report report : reports) {
    if (report instanceof SalesReport) {
        System.out.println("Sales report");
    } else if (report instanceof AuditReport) {
        System.out.println("Audit report");
    } else if (report instanceof FinanceReport) {
        System.out.println("Finance report");
    }
}

```

Перестрой модель так, чтобы:

- общий цикл не знал о конкретных типах отчётов;
- каждый отчёт сам определял своё описание;
- при добавлении нового вида отчёта существующий цикл не приходилось изменять.

### Пример

```text
Входные данные:
SalesReport
AuditReport
FinanceReport

Результат:
Sales report
Audit report
Finance report

```

### Ограничение

В итоговом цикле не должно быть:

```java
instanceof

```

и строковых признаков типа:

```text
"SALES"
"AUDIT"
"FINANCE"

```

# Challenge

## Задача 9. Рефакторинг системы файлов

**Challenge**

**Ориентировочное время:** 25–30 минут

В программе все файлы представлены одним классом:

```java
class StoredFile {
    String type;
    String name;
    int size;

    StoredFile(
            String type,
            String name,
            int size
    ) {
        this.type = type;
        this.name = name;
        this.size = size;
    }
}

```

Основной код выглядит примерно так:

```java
if (file.type.equals("TEXT")) {
    System.out.println(
            "Text file: " + file.name
    );
} else if (file.type.equals("IMAGE")) {
    System.out.println(
            "Image file: " + file.name
    );
} else if (file.type.equals("VIDEO")) {
    System.out.println(
            "Video file: " + file.name
    );
}

```

Подобные проверки встречаются и в других частях программы.

Для каждого типа по-разному определяется стоимость хранения одного файла:

```text
TEXT
→ size * 1

IMAGE
→ size * 2

VIDEO
→ size * 5

```

Также каждый тип имеет собственное описание.

Нужно переработать модель так, чтобы:

- тип файла не хранился строкой;
- общие данные не дублировались;
- существовал общий тип для файлов;
- если создание «просто файла» не имеет смысла, модель это отражала;
- каждый конкретный тип сам определял:
    - описание;
    - стоимость хранения;
- разные файлы можно было хранить в одном массиве;
- один общий цикл:
    - выводил описание;
    - вычислял стоимость хранения;
    - находил общую стоимость всех файлов;
    - находил самый дорогой файл;
- основной алгоритм не содержал `if / else` по конкретным типам.

После рефакторинга добавь:

```text
ArchiveFile

```

Правило:

```text
стоимость хранения
→ size * 3

```

После добавления нового типа существующий общий цикл менять нельзя.

### Пример

```text
Входные данные:
TextFile("notes.txt", 10)
ImageFile("photo.png", 20)
VideoFile("lesson.mp4", 100)

Результат:
Text file: notes.txt, storage: 10
Image file: photo.png, storage: 40
Video file: lesson.mp4, storage: 500
Total storage cost: 550
Most expensive: lesson.mp4

```

### Подсказка

Найди операции, для которых сейчас приходится спрашивать:

```text
какой это тип файла?

```

Если операция существует у всех файлов, но выполняется по-разному, вероятно, различающееся поведение должно находиться в самих объектах.
