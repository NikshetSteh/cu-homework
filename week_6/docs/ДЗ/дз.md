# Java 1. Неделя 6 — Домашнее задание

## Пакетная обработка команд устройства

### Цель

Закрепить работу с исключениями на одной связной задаче:

- различать обычный и исключительный сценарий;
- использовать стандартные исключения;
- создавать собственные исключения;
- выбирать checked или unchecked вариант;
- использовать `throw` и `throws`;
- выбирать место для `catch`;
- понимать распространение исключений;
- использовать `AutoCloseable`;
- применять try-with-resources;
- не превращать программу в один большой `try-catch`.

---

# Задача. Пакетная обработка команд

Есть массив команд:

```java
String[] commands = {
        "VOLUME:30",
        "VOLUME:abc",
        "MODE:SAFE",
        "VOLUME:120",
        "UNKNOWN",
        "STOP"
};
```

Нужно реализовать обработчик команд устройства.

Поддерживаются команды:

```text
VOLUME:<number>
MODE:<name>
STOP
```

Программа должна последовательно обрабатывать элементы массива и выполнять соответствующие действия.

---

# 1. Команда `VOLUME`

Формат:

```text
VOLUME:<number>
```

Например:

```text
VOLUME:30
VOLUME:0
VOLUME:100
```

Допустимый диапазон:

```text
0..100
```

При корректном значении вывести:

```text
Volume set to <value>
```

Например:

```text
Volume set to 30
```

## Возможные проблемы

### Значение не является числом

Например:

```text
VOLUME:abc
```

При преобразовании должно использоваться стандартное исключение Java.

Не нужно заранее вручную проверять каждый символ строки.

---

### Значение вне диапазона

Например:

```text
VOLUME:120
```

Создай собственное исключение:

```text
InvalidVolumeException
```

Оно должно использоваться, если число удалось получить, но оно не входит в диапазон:

```text
0..100
```

Самостоятельно реши:

```text
InvalidVolumeException
→ checked
или
→ unchecked
```

Выбор нужно уметь объяснить.

---

# 2. Команда `MODE`

Формат:

```text
MODE:<name>
```

Допустимые режимы:

```text
SAFE
FAST
SILENT
```

При корректной команде вывести:

```text
Mode set to <name>
```

Например:

```text
MODE:SAFE
```

Результат:

```text
Mode set to SAFE
```

## Неизвестный режим

Например:

```text
MODE:TURBO
```

Самостоятельно определи контракт.

Это может быть:

```text
обычный неуспешный результат
```

или:

```text
исключительная ситуация
→ собственное исключение
```

Оба подхода допустимы, если решение:

- последовательное;
- отражено в коде;
- можно объяснить через контракт метода.

Если выбираешь исключение — придумай для него понятный тип.

---

# 3. Неизвестная команда

Например:

```text
RESET
```

или:

```text
UNKNOWN
```

Такой команды нет среди поддерживаемых.

Самостоятельно реши:

```text
неизвестная команда
→ обычный результат
```

или:

```text
неизвестная команда
→ exception
```

Выбор должен быть согласован с остальной моделью программы.

Не используй общий:

```java
throw new Exception(...);
```

если можно выразить проблему точнее.

---

# 4. Команда `STOP`

Команда:

```text
STOP
```

является **обычным сценарием завершения обработки**.

После неё следующие элементы массива не выполняются.

Например:

```java
String[] commands = {
        "VOLUME:20",
        "STOP",
        "VOLUME:80"
};
```

Результат не должен содержать:

```text
Volume set to 80
```

`STOP` не нужно превращать в исключение только для выхода из цикла.

---

# 5. Поведение при ошибке одной команды

В массиве могут встречаться как корректные, так и некорректные команды.

Например:

```java
String[] commands = {
        "VOLUME:20",
        "VOLUME:abc",
        "MODE:SAFE"
};
```

Самостоятельно выбери стратегию.

## Вариант A

```text
ошибка одной команды
↓
завершает обработку всего пакета
```

## Вариант B

```text
ошибка одной команды
↓
обрабатывается
↓
переходим к следующей команде
```

Оба варианта допустимы.

Главное:

- исключение нельзя молча игнорировать;
- поведение должно быть одинаковым для одинаковых типов ошибок;
- место `catch` должно соответствовать выбранной стратегии;
- ваше решение необходимо уметь обосновать.

---

# 6. `DeviceSession`

Обработка команд должна выполняться внутри объекта:

```text
DeviceSession
```

`DeviceSession` должен реализовывать:

```java
AutoCloseable
```

Минимально у класса должны быть:

```text
состояние сессии
+
методы выполнения команд
+
close()
```

При открытии сессии можно выводить:

```text
Session opened
```

При закрытии обязательно выводить:

```text
Session closed
```

---

# 7. Try-with-resources

Работу с `DeviceSession` организуй через try-with-resources:

```java
try (DeviceSession session = ...) {
    ...
}
```

Сессия должна закрываться:

```text
при обычном завершении
```

```text
при STOP
```

```text
при возникновении исключения
```

Не вызывай `close()` вручную после try-with-resources.

---

# 8. Декомпозиция

Не помещай всю программу в один метод и один большой `try-catch`.

Раздели решение хотя бы по следующим обязанностям:

```text
разобрать команду
↓
определить её тип
↓
выполнить команду
↓
обработать ошибочный сценарий
↓
управлять жизненным циклом DeviceSession
```

Конкретные имена и количество методов выбери самостоятельно.

Главное — каждый метод должен решать понятную задачу.

---

# 10. Ограничения

Не используй:

- коллекции;
- Stream API;
- lambda;
- generics, кроме уже встречающихся в стандартном коде;
- файлы;
- сторонние библиотеки.

Не используй исключения как замену обычному управлению потоком.

Например:

```text
STOP
→ обычное завершение цикла
```

а не:

```text
STOP
→ throw StopException
```

без содержательной причины.

Не используй:

```java
catch (Exception e)
```

как единственный обработчик всех возможных ошибок.

# Итоговая модель

В этой задаче нужно самостоятельно собрать несколько идей недели:

```text
обычная команда
→ обычное управление потоком
```

```text
некорректные данные
→ standard exception
```

```text
нарушение правила приложения
→ custom exception
```

```text
exception
→ распространяется
→ catch на выбранном уровне
```

```text
DeviceSession
→ AutoCloseable
→ try-with-resources
→ close()
```

Главная цель — не просто добиться правильного вывода, а построить понятную модель ошибок и уметь объяснить решения в собственном коде.
