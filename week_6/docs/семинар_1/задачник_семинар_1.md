# 2. Рефакторинг: exception не должен заменять обычную логику

## Задача 2. Рефакторинг очереди печати

**Обязательная**

**Ориентировочное время:** 12 минут

В проекте есть класс:

```java
public class PrintQueue {

    private int freeSlots;

    public PrintQueue(int freeSlots) {
        this.freeSlots = freeSlots;
    }

    public void addJob(int pages) throws Exception {
        if (pages <= 0) {
            throw new Exception("Invalid pages");
        }

        if (freeSlots == 0) {
            throw new Exception("Queue is full");
        }

        freeSlots--;
    }

    public int getFreeSlots() {
        return freeSlots;
    }
}
```

Вызывающий код:

```java
try {
    queue.addJob(25);
    System.out.println("Job added");

} catch (Exception e) {
    System.out.println(
            "Cannot add job: " + e.getMessage()
    );
}
```

Код работает, но смешивает разные по смыслу ситуации.

Проведи рефакторинг.

### Требования

#### Случай 1

```text
pages <= 0
```

Это нарушение контракта метода.

Используй подходящее стандартное unchecked-исключение.

#### Случай 2

```text
freeSlots == 0
```

Полная очередь — нормальный ожидаемый исход попытки добавить задание.

Не используй exception для этой ветки.

Измени контракт метода так, чтобы вызывающий код мог узнать:

```text
задание добавлено
или
очередь заполнена
```

без `catch`.

#### Случай 3

Убери:

```java
throws Exception
```

и общий:

```java
throw new Exception(...)
```

из метода.

### Пример 1

```text
Исходные данные:
freeSlots = 2
pages = 25

Результат:
Job added
freeSlots = 1
```

### Пример 2

```text
Исходные данные:
freeSlots = 0
pages = 25

Результат:
Queue is full
freeSlots = 0
```

### Дополнительная проверка

```text
Исходные данные:
freeSlots = 2
pages = 0

Результат:
IllegalArgumentException
freeSlots = 2
```

### После рефакторинга

Объясни:

```text
полная очередь
→ обычный результат

pages <= 0
→ нарушение контракта
→ exception
```

И ответь:

> Почему `throws Exception` был слишком слабым контрактом метода?

# 3. Иерархия исключений и порядок `catch`

## Задача 3. Исправь обработчики

**Обязательная**

**Ориентировочное время:** 10 минут

Дан код:

```java
static void process(String[] values, String rawIndex) {
    try {
        int index = Integer.parseInt(rawIndex);
        int value = Integer.parseInt(values[index]);

        System.out.println(100 / value);

    } catch (RuntimeException e) {
        System.out.println("Runtime problem");

    } catch (NumberFormatException e) {
        System.out.println("Invalid number");

    } catch (ArrayIndexOutOfBoundsException e) {
        System.out.println("Invalid index");
    }
}
```

В таком виде код содержит проблему.

### Часть 1. Разбор

Не меняя код, ответь:

1. Почему некоторые `catch` здесь недостижимы?
2. Как связаны:
    - `RuntimeException`;
    - `NumberFormatException`;
    - `ArrayIndexOutOfBoundsException`;
    - `ArithmeticException`?
3. Что произойдёт, если оставить только `catch (RuntimeException e)`?
4. Почему это технически работает, но ухудшает смысл обработки?

### Часть 2. Исправление

Перестрой обработчики так, чтобы программа различала:

```text
rawIndex не число
→ Invalid index format

индекс вне массива
→ Index is out of range

элемент массива не число
→ Invalid value

значение равно 0
→ Division by zero
```

### Пример 1

```text
Входные данные:
values = {"5", "10", "20"}
rawIndex = "abc"

Результат:
Invalid index format
```

### Пример 2

```text
Входные данные:
values = {"5", "0", "20"}
rawIndex = "1"

Результат:
Division by zero
```

### Важное уточнение

Одного только типа `NumberFormatException` недостаточно, чтобы автоматически понять:

```text
не удалось разобрать rawIndex
или
не удалось разобрать values[index]
```

Подумай, как изменить структуру `try`, чтобы обработка оставалась понятной.

# 4. Проектируем собственное исключение

## Задача 4. Активация пропуска

**Обязательная**

**Ориентировочное время:** 12 минут

Есть класс:

```text
AccessPass
```

Он хранит:

```text
id
activated
blocked
```

Нужно реализовать операцию:

```java
void activate()
```

В системе есть две разные прикладные проблемы:

```text
пропуск заблокирован
пропуск уже был активирован
```

Создай для них собственные типы исключений:

```text
BlockedPassException
AlreadyActivatedException
```

### Требования

1. Оба исключения должны иметь понятные имена.
2. У каждого должен быть конструктор с сообщением.
3. `activate()` должен выбрасывать подходящий тип в зависимости от состояния.
4. Если пропуск можно активировать:
    - `activated` становится `true`;
    - метод завершается нормально.
5. Вызывающий код должен иметь возможность **по-разному реагировать** на две ошибки.

Самостоятельно выбери:

```text
checked
или
unchecked
```

для этих исключений.

Главное — объяснить решение.

### Пример 1

```text
Исходное состояние:
blocked = false
activated = false

Результат:
Pass activated
activated = true
```

### Пример 2

```text
Исходное состояние:
blocked = true
activated = false

Результат:
BlockedPassException
activated = false
```

### После решения

Ответь:

1. Почему здесь полезнее два типа исключений, а не один `Exception` с разными сообщениями?
2. Что станет проще в вызывающем коде?
3. Что изменилось бы в сигнатуре `activate()`, если выбрать checked-вариант?
4. Что изменилось бы при unchecked-варианте?

# 5. Распространение исключения и место обработки

## Задача 5. Импорт конфигурации

**Обязательная**

**Ориентировочное время:** 11 минут

Построй цепочку:

```text
runImport(...)
↓
buildConfig(...)
↓
parsePort(...)
```

### `parsePort(String rawPort)`

Преобразует строку в число.

Стандартное исключение преобразования внутри метода **не перехватывай**.

### `buildConfig(String host, String rawPort)`

Должен:

1. получить порт через `parsePort(...)`;
2. проверить диапазон:

```text
1..65535
```

3. если порт вне диапазона — выбросить собственное исключение:

```text
InvalidPortException
```

4. если всё корректно — вернуть объект:

```text
ServerConfig
```

с полями:

```text
host
port
```

### `runImport(...)`

Это верхний уровень сценария.

Именно он знает, что пользователю нужно сообщить:

```text
Configuration import failed
```

Реши:

- где обработать `NumberFormatException`;
- где обработать `InvalidPortException`;
- нужно ли `buildConfig(...)` объявлять `throws`;
- какие исключения должны пройти через промежуточные методы.

### Пример 1

```text
Входные данные:
host = "cache.local"
rawPort = "6379"

Результат:
Configuration imported: cache.local:6379
```

### Пример 2

```text
Входные данные:
host = "cache.local"
rawPort = "70000"

Результат:
Configuration import failed: invalid port
```

### Дополнительная проверка

```text
rawPort = "six"
```

Результат должен отличаться по причине ошибки от случая `70000`.

### После решения

Нарисуй путь для обоих ошибочных сценариев:

```text
место возникновения
↓
через какие методы проходит exception
↓
место catch
```

# 6. Рефакторинг управления ресурсом

## Задача 6. От ручного `close()` к try-with-resources

**Обязательная**

**Ориентировочное время:** 10 минут

Дан учебный ресурс:

```java
public class ScannerDevice implements AutoCloseable {

    private final String id;

    public ScannerDevice(String id) {
        this.id = id;
        System.out.println("Scanner opened");
    }

    public void scan(String command) {
        System.out.println("Command: " + command);

        if ("BROKEN".equals(command)) {
            throw new IllegalStateException(
                    "Scanner failure"
            );
        }
    }

    @Override
    public void close() {
        System.out.println("Scanner closed");
    }
}
```

И код использования:

```java
ScannerDevice scanner =
        new ScannerDevice("S-10");

scanner.scan(command);

scanner.close();
```

### Часть 1. Найди проблему

Объясни, почему:

```java
scanner.close();
```

может не выполниться.

Покажи конкретный сценарий.

### Часть 2. Исправь через `finally`

Перепиши код так, чтобы ресурс закрывался независимо от результата `scan(...)`.

### Часть 3. Проведи рефакторинг

После этого замени ручной `try-finally` на try-with-resources.

### Пример 1

```text
Входные данные:
command = "SCAN"

Результат:
Scanner opened
Command: SCAN
Scanner closed
```

### Пример 2

```text
Входные данные:
command = "BROKEN"

Результат содержит:
Scanner opened
Command: BROKEN
Scanner closed
```

Исключение при этом не должно молча исчезнуть.

### После решения

Объясни цепочку:

```text
ScannerDevice
↓ implements
AutoCloseable
↓
close()
↓
try-with-resources
↓
автоматический вызов close()
```

И отдельно ответь:

> Почему try-with-resources решает задачу закрытия ресурса, но сам по себе не является способом обработки `IllegalStateException`?

# Challenge

## Challenge. Пакетная обработка команд

**Challenge**

**Ориентировочное время:** 30–40 минут

Есть массив:

```java
String[] commands = {
        "VOLUME:30",
        "VOLUME:abc",
        "MODE:SAFE",
        "VOLUME:120",
        "UNKNOWN",
        "STOP"
};
```

Нужно реализовать небольшой обработчик команд устройства.

Поддерживаются:

```text
VOLUME:<number>
MODE:<name>
STOP
```

### `VOLUME:<number>`

Возможны две проблемы:

```text
значение не число
→ стандартное исключение преобразования

значение вне диапазона 0..100
→ собственное InvalidVolumeException
```

### `MODE:<name>`

Допустимы:

```text
SAFE
FAST
SILENT
```

Для неизвестного режима самостоятельно реши:

```text
обычный неуспешный результат
или
собственное исключение
```

Выбор нужно обосновать.

### Неизвестная команда

Например:

```text
UNKNOWN
```

Самостоятельно задай контракт обработки.

### `STOP`

Это обычная команда завершения:

```text
STOP
→ прекращаем обработку массива
```

### Ресурс

Вся обработка выполняется внутри:

```text
DeviceSession
```

который реализует:

```java
AutoCloseable
```

Используй try-with-resources.

### Архитектурное требование

Не помещай весь код в один огромный `try-catch`.

Раздели программу хотя бы по смыслу:

```text
разобрать команду
↓
выполнить команду
↓
обработать ошибку
↓
управлять жизненным циклом сессии
```

### Пример 1

```text
Входные данные:
commands = {
    "VOLUME:30",
    "MODE:SAFE",
    "STOP"
}

Результат:
Volume set to 30
Mode set to SAFE
Session closed
```

### Пример 2

```text
Входные данные:
commands = {
    "VOLUME:abc",
    "MODE:FAST"
}
```

Точный результат зависит от того, решил ли ты:

```text
ошибка одной команды
→ завершает весь пакет
```

или:

```text
ошибка одной команды
→ обрабатывается
→ переходим к следующей
```

Оба варианта допустимы, если:

- решение последовательное;
- исключение не игнорируется;
- `DeviceSession` гарантированно закрывается;
- место `catch` можно объяснить.

### Ограничения

Не используй:

- коллекции;
- Stream API;
- lambda;
- файлы;
- сторонние библиотеки.

### Подсказка

Перед кодом выпиши отдельно:

```text
какие ситуации являются нормальными
какие являются исключительными
какие exception-типы нужны
на каком уровне нужен catch
```

После этого проектировать методы будет проще.
